# 大模型工程师知识图谱

> 入口：[总索引](README.md)。先修、评测和验收分别见[基础与模型原理](基础与模型原理.md)、[评测与实验方法](评测与实验方法.md)、[实践与验收清单](实践与验收清单.md)。

## 岗位分支与先修顺序

共同起点：Python/张量与 HTTP 基础 → 模型与数据边界 → 评测基线。随后按岗位选主线，不要求人人先学完整预训练。

| 目标 | 主线 | 阶段验收 |
| --- | --- | --- |
| 应用工程 | [Prompt](Prompt%20工程完整知识体系.md) → [RAG](RAG知识体系.md) → 按需 [Agent](Agent%20知识体系.md) | 部署/闭环并行；先可溯源问答，再 mock 工具与恢复，不默认多 Agent |
| 推理/平台 | Transformer/KV/数值 → [推理部署](推理部署完整知识体系.md) → [生命周期](模型全生命周期闭环知识体系.md) | 质量、容量与负载基线，再量化、分离式部署、多卡通信 |
| 训练/算法工程 | 模型/优化/数据 → CS336 实现 → [LLM 训练](LLM训练知识体系.md) | 小模型 loss/mask/checkpoint，再 SFT/偏好优化与分布式 |

[多模态](多模态知识体系.md)按业务选择：视觉语言是本目录主线，语音、生成、VLA 另补原理与验收。安全、权限、成本与回归全程必修。下列主题图谱用于查漏，不代表每个岗位都要顺序学完。

**必修层级与停止条件**

“必修”指目标岗位的最低能力，不要求每个岗位实现所有算法；选修由实际业务问题触发，不按工具数量衡量进度。

| 层级 | 内容与入口 | 达到什么程度再进阶 |
| --- | --- | --- |
| 所有岗位共修 | [基础](基础与模型原理.md)、[评测](评测与实验方法.md)、数据授权/安全、版本与成本 | 能解释张量/模型边界；有基线、集合隔离、失败记录；分开质量与门禁 |
| 应用岗必修 | [Prompt](Prompt%20工程完整知识体系.md)、[RAG](RAG知识体系.md)、HTTP 服务与闭环 | 可溯源问答、无依据处理、权限过滤、更新回归；先跑[端到端案例](端到端RAG教学案例.md) |
| 应用岗条件必修 | [Agent](Agent%20知识体系.md)：仅在任务需要工具或外部行动时 | mock 回执、参数绑定、审批、幂等与恢复通过后再接真实工具 |
| 平台岗必修 | Transformer/KV/数值、[推理部署](推理部署完整知识体系.md)、[生命周期](模型全生命周期闭环知识体系.md) | 固定负载下质量、时延、吞吐、取消/过载与回滚有证据 |
| 训练岗必修 | CS336 实现、[训练](LLM训练知识体系.md)、数据与恢复 | loss/mask、有效 token 加权、小样本过拟合、独立验证与中断恢复 |
| 训练岗条件必修 | 分布式：单卡容量/吞吐不足；偏好优化：确有偏好/奖励目标 | 先证明基线正确，再测显存/通信或奖励与能力退化；不默认上 RL |
| 按业务选修 | 多模态、MoE/EP、模型合并、蒸馏、测试时计算、多 Agent | 说明要解决的瓶颈，提供对照收益与额外成本；没有需求可暂缓 |

## 一、基础能力(Fundamentals)

层级：共修；先用 Python/PyTorch 完成最小例子，其他框架按业务选学。

- 数学基础
    - 线性代数：矩阵、向量、特征值
    - 概率统计：贝叶斯、分布、期望
    - 微积分：梯度、链式法则
- 编程能力
    - Python
    - PyTorch / TensorFlow
    - NumPy / Pandas
- 计算机基础
    - 操作系统(Linux)
    - 网络：HTTP、API
    - 数据结构与算法

## 二、模型原理(Model Core)

层级：核心概念共修；算子实现与数值推导是训练/平台岗必修，应用岗按排障需要深入。

- Transformer架构
    - Self‑Attention
    - Multi‑Head‑Attention
    - Positional Encoding位置编码
- 语言模型谱系
    - GPT(生成式)
    - BERT(编码器)
    - T5(编解码)
- Tokenizer分词机制
    - BPE / SentencePiece
    - Token成本与上下文窗口关系

## 三、训练体系(Training Pipeline)

层级：训练岗必修；应用/平台岗理解数据与适配边界，不要求完整预训练或逐项实现 RLHF/DPO/GRPO。

- 预训练
    - 大规模语料
    - 自监督学习
- 微调技术
    - SFT有监督微调
    - RLHF
    - DPO
    - GRPO
- 数据工程
    - 数据集清洗
    - 数据标注
    - 去重与质量控制

## 四、推理与优化(Inference & Optimization)

层级：采样与上下文边界共修；调度、量化与内核优化是平台岗必修，具体算法按瓶颈选学。

- 推理策略
    - Temperature、Top‑P、Top‑K
    - Beam Search
- 性能优化
    - KV‑Cache
    - Continuous Batching连续批处理
    - Speculative Decoding投机解码
- 模型压缩
    - 量化：INT8、INT4、GPTQ、AWQ

## 五、工程架构(Engineering System)

层级：HTTP、错误处理、监控与发布共修；自托管容量规划是平台岗必修，不必同时掌握全部运行时。

- 推理运行时
    - vLLM
    - TensorRT‑LLM
    - ONNX Runtime
    - Ollama / Llama.cpp
- 部署方式
    - 云API
    - 私有化部署
    - 边缘部署
- 服务架构
    - FastAPI / Flask
    - 负载均衡
    - 可观测性监控

## 六、RAG系统(核心能力)

层级：知识问答应用岗必修；其他岗位了解版本/权限与检索-生成边界即可。

- 基本流程：用户查询 → 检索 → 拼接上下文 → 生成回答
- 核心组件
    - Embedding向量模型
    - 向量数据库
    - 检索算法：向量检索 / BM25
    - Chunk分块：大小、overlap重叠
    - Rerank重排
- 优化策略
    - 多查询改写

## 七、Prompt工程

层级：结构化输出、上下文和注入边界共修；复杂模板与改写技巧按任务选学。

- 基础技巧
    - 角色设定
    - Few‑shot
    - 输出格式控制
- 高级技巧
    - CoT思维链
    - ReAct
    - Prompt模版化

## 八、Agent系统

层级：有外部行动需求时条件必修；先确定性工作流和 mock 工具，再考虑规划器与多 Agent。

- 核心能力
    - 任务拆解
    - 工具调用
    - 多步推理
- 关键组件
    - Memory记忆
    - Planner规划器
    - Executor执行器
- 常用框架
    - LangChain
    - LlamaIndex
    - AutoGPT
    - CrewAI

## 九、评估体系(Evaluation)

层级：共修；任务质量、引用、权限与格式分开评测，LLM 评分需人工校准，不能只报聚合分数。

- 自动评估
    - Perplexity
    - BLEU / ROUGE
    - LLM‑as‑Judge
- Benchmark测试集
- 人工评估
    - 准确性
    - 可读性
    - 安全性

## 十、安全与对齐

层级：共修；模型输出约束不替代后端权限、数据授权和外部行动审批。

- 风险类型
    - 幻觉(Hallucination)
    - 偏见(Bias)
    - 越界输出(Jailbreak)
    - 检索/工具中的 Prompt 注入、越权与敏感数据外传
- 防护策略
    - Prompt层防护
    - 输出审查
    - 可信身份与 ACL、最小权限、审批参数绑定、审计与恢复

## 十一、性能指标

层级：成本与基本时延共修；平台岗需实测长度分布、到达率、TTFT/TPOT、尾延迟、有效吞吐与失败率。

- Latency延迟
- Throughput吞吐量
- GPU显存占用
- Token/s

## 十二、成长路径

- 入门：能解释基础，交付目标岗位的最小项目与失败测试，不以“调用过 API”判定掌握
- 进阶：按岗位补应用可靠性、训练正确性或服务容量，提供可复现的对照实验
- 高级：架构设计、可靠性与评测治理；按需求学习模型适配与多 Agent，不能用某条岗位路线代替全部成长路径
