# 多模态训练完整知识体系

> 本卷以视觉语言理解与训练为主，不是完整音频、图像生成或具身智能教材。先修见[基础](基础与模型原理.md)，评估与项目见[评测方法](评测与实验方法.md)、[实践验收](实践与验收清单.md)；返回[总索引](README.md)。

## 一、多模态训练基础认知

- 核心定义
  - 全称：多模态大模型训练（Multimodal Large Language Model Training）
  - 核心解决：让模型从「只懂文本」变成「能看、能听、能理解图文视频」的通用智能体
  - 本质：在 LLM 主干上挂载感知模块，通过模态对齐训练让不同模态在统一语义空间中对齐
- 与纯文本 LLM 训练的本质区别 【多模态独有】
  - 纯文本 LLM：单一模态，输入输出都是 token 序列
  - 多模态模型：多种模态输入（图像/视频/音频），输出仍是文本（或跨模态生成）
  - 核心差异：多了「模态对齐」这一关——不同模态的表示必须映射到同一语义空间
  - 更深差异：即使对齐看似成功，模型仍可能绕过视觉，走语言捷径
- 常见训练模块（不等于三个必经阶段）【多模态独有】
  - 表示与连接器适配：复用或训练视觉 encoder，让其特征可被语言模型利用
  - 多模态预训练：在大规模图文/视频数据上训练跨模态理解能力
  - 多模态 SFT / 对齐：教会模型遵循多模态指令，输出符合人类偏好
- 核心价值
  - 感知扩展：接入 LLM 本身不具备的视觉/听觉能力
  - 任务扩展：OCR、文档理解、图表问答、视频理解、VLA
  - 交互扩展：支持图文混合输入、多轮多模态对话
- 文档定位声明
  - 本体系定位多模态训练工程视角
  - 不含纯文本 LLM 训练内容（见[LLM 训练完整知识体系](LLM训练知识体系.md)）
  - 不含多模态推理部署（量化、KV Cache、推理引擎等属于推理部署体系）
  - 不含哲学讨论
  - 但视觉幻觉有一部分踩在范式天花板上，不是纯工程债，安全章节会留指针
  - **【定稿】本卷以视觉为主，音频仅作占位，不展开（speech token、连续音频离散化、ASR 与图文对齐的本质差异不在本卷范围内）**
  - **【定稿】密集预测输出头（分割/检测）、crop-based 视觉推理属于 CV 任务层或推理侧策略，不在本卷范围内**

## 二、多模态训练完整工作流程

- 先区分两种训练对象
  - 视觉编码器预训练：如 CLIP/SigLIP，训练图文编码器以获得语义表示；数据规模、损失和可训练参数由论文或实验确定
  - VLM 连接器对齐：连接已有视觉 encoder 与 LLM，用图文生成等目标训练 projector，可能冻结两端；不等于重新做 CLIP 预训练，也不统一要求数亿至数十亿图文对
- 以下是一种基于已有视觉 encoder 的分阶段配方，不是统一必经流程【多模态独有】
  - Phase 1：连接器对齐（Connector Alignment）
    - 目标：把已有视觉特征映射为语言模型可用的表示
    - 数据：质量受控的图文对；规模按起点、预算、消融和验证集确定
    - 方法：条件文本生成；对比目标仅在架构提供相应编码器与训练头时使用
    - 冻结策略示例：冻结 ViT 与 LLM，只训 projector
    - 产出：训练后的 projector 与原有冻结权重；不能声称冻结的 encoder 被重新训练
    - 风险：对齐看似成功，模型仍可能走语言捷径 【新增】
  - Phase 2：多模态预训练（Multimodal Pre-training）
    - 目标：在大规模图文/视频数据上训练跨模态理解能力
    - 数据：图文对 + 交错图文（interleaved）+ 视频
    - 方法：常用条件自回归生成，也可按模型设计加入其他目标，不强制混合对比学习
    - 冻结策略：projector + LLM，或包括视觉侧的联合训练；显式列出可训练参数
    - 产出：多模态 Base Model
  - Phase 3：多模态 SFT（Multimodal Instruction Tuning）
    - 目标：教会模型遵循多模态指令
    - 数据：多模态指令-回答对；数量不是统一质量或能力门槛
    - 方法：监督学习，与纯文本 SFT 相同 【共享】
    - 产出：多模态 Instruct Model
  - Phase 4：多模态对齐（Multimodal Alignment，可选）
    - 目标：让多模态输出符合人类偏好
    - 数据：多模态偏好数据
    - 方法：RLHF / DPO / GRPO 【共享】
    - 产出：多模态 Aligned Model
- 关键认知
  - 表示兼容与视觉利用是训练目标，不一定是独立的第一阶段
  - 对齐成功后还有第二关：模态捷径——模型可能绕过视觉，走语言先验 【新增】
  - 四阶段不是必须严格串行，生产系统常做阶段融合
  - 纯文本训练也不强制“预训练 → SFT → 偏好优化”；多模态的额外约束是表示、连接器、processor 和训练目标的兼容，不是固定多一步
- 论文配方对照（历史实例，不代表所有模型）
  - LLaVA-1.5：已有 CLIP 视觉塔 + MLP；先训练连接器，再进行视觉指令微调，并非从零训练数十亿图文对的视觉塔。见[论文（2023）](https://arxiv.org/abs/2310.03744)
  - Qwen2-VL：视觉塔初始化自 DFN ViT 并修改位置编码；先训练视觉侧，再全参数预训练，指令微调阶段冻结 ViT。见[论文 §2.2（2024）](https://arxiv.org/html/2409.12191v1#S2.SS2)

### 2.1 已有视觉编码器的连接器对齐流程 【多模态独有】

- Step 1：视觉 encoder 选型
  - CLIP ViT：OpenAI CLIP 的视觉塔，最常用
  - SigLIP：采用成对 sigmoid 损失的图文预训练实例；与 CLIP 的批内 softmax 目标不同，不保证所有配置都更稳定
  - DINOv2：Meta 的自监督视觉模型，视觉特征强
  - 选型维度：视觉特征质量、训练数据规模、推理速度、许可证
- Step 2：对齐模块设计
  - MLP Projector：最简单，2-3 层 MLP，LLaVA 系使用
  - Q-Former：Query Transformer，用可学习 query 压缩视觉特征，BLIP-2 使用
  - Resampler：Perceiver 风格的注意力重采样，Flamingo 使用
  - 选型维度：压缩比、训练难度、表达能力
- Step 3：冻结策略
  - 冻结 ViT + 冻结 LLM，只训 projector：连接器适配的常见起点
  - 冻结 ViT，训练 projector + LLM：让语言侧适应视觉条件；解冻 LLM 就应列为可训练对象
  - 训练 ViT + projector + LLM：联合适配，成本与遗忘风险较高，效果需验证
- Step 4：对齐训练目标
  - 条件文本生成：让语言模型基于视觉特征生成 caption，常用自回归交叉熵
  - 若设计包含图文检索/对比训练头，可加入对比目标；不能把仅训练 projector 的生成目标直接称为 CLIP 预训练
- Step 5：数据准备
  - 数据规模：由初始化、目标和学习曲线确定；已有编码器连接器适配与从零视觉预训练分别估算，不使用统一规模下限
  - 数据来源：LAION、DataComp、内部数据
  - 数据质量：质量过滤 + 去重 + 图文匹配度评估
  - Re-captioning：用 VLM/LLM 重写详细 caption，替代原始 alt-text 【新增】
- Step 6：评估
  - 生成与理解：caption 忠实度、图文问答、OCR 等任务留出集
  - 图文检索/零样本分类：仅对支持配套文本编码器或明确候选评分协议的模型使用，并说明评分方式
  - 模态捷径：同题原图、遮图、错配图对照，按视觉依赖类别分析 【新增】

## 三、核心组件详解

### 3.1 视觉 encoder 与挂载方式 【多模态独有】

- 视觉 encoder 选型
  - ViT（Vision Transformer）
    - 标准架构，patch embedding + transformer
    - 变体：ViT-B/L/H，不同规模
    - 训练方式：监督（ImageNet）或自监督（MAE、DINO）
  - CLIP ViT
    - 图文对比学习训练，视觉特征与文本语义对齐
    - 优势：开箱即用，语义对齐好
    - 采用者：LLaVA、Qwen-VL
  - SigLIP
    - 采用成对 sigmoid 图文损失，不依赖 CLIP 式的批内 softmax 归一化
    - 特点：提供不同批大小下的训练取舍，效果依配置评估
    - 采用实例：PaliGemma；Qwen2-VL 使用 DFN 初始化的 ViT，不属于此例
  - DINOv2
    - 自监督视觉模型，视觉特征强
    - 优势：无需文本标注，视觉表示质量高
    - 劣势：与文本语义不对齐，需要额外对齐
  - 选型维度
    - 视觉特征质量：分类、检测、分割任务表现
    - 语义对齐度：与文本的天然对齐程度
    - 推理速度：影响端到端延迟
    - 许可证：商用友好度
- 对齐模块设计
  - MLP Projector
    - 结构：2-3 层 MLP，把视觉特征映射到 LLM 隐空间
    - 优势：简单、训练快
    - 劣势：压缩比低，视觉 token 多
    - 采用者：LLaVA、LLaVA-1.5
  - Q-Former
    - 结构：用可学习 query 从视觉特征中提取信息
    - 优势：压缩比高，视觉 token 少
    - 劣势：训练复杂，需要两阶段训练
    - 采用者：BLIP-2、InstructBLIP
  - Resampler（Perceiver Resampler）
    - 结构：Perceiver 风格的注意力重采样
    - 优势：压缩比可调，表达能力强
    - 采用者：Flamingo、Idefics
  - 选型判断
    - 简单场景：MLP Projector
    - 高压缩比需求：Q-Former 或 Resampler
    - 追求效果：Resampler
- 冻结/解冻策略
  - 全冻结（只训 projector）：训练快，效果有限
  - 冻 ViT 解冻 LLM：让 LLM 适应视觉 token，常用
  - 解冻 ViT 冻 LLM：让视觉适应文本，少用
  - 全解冻：效果可能最好，成本最高
  - 分阶段解冻：先冻后解，平衡成本与效果

### 3.2 对比预训练与连接器对齐 【多模态独有】

- CLIP 式图文对比学习
  - 核心：图文对做 InfoNCE 损失，让匹配的图文在语义空间靠近
  - 损失函数：对比损失，正样本拉近，负样本推远
  - 可训练对象：通常为视觉/文本编码器及相应缩放参数；不能与冻结两端只训 projector 的配方混为一谈
  - 局限：该目标本身不训练自回归生成，语义表示质量需在任务上验证
- 生成式 caption 预训练
  - 核心：让模型为图像生成描述文本
  - 损失函数：自回归交叉熵
  - 优势：直接学生成，与下游任务一致
  - 局限：需要高质量 caption 数据
- 混合目标
  - 对比 + 生成联合训练
  - 优势：兼顾对齐和生成
  - 采用者：部分生产系统
- 关键认知
  - 表示适配、视觉特征质量、数据与后续训练共同影响效果，不能由连接器对齐成绩单独推出能力上限

- **【新增】模态捷径与视觉幻觉**
  - **模态捷径（Language Shortcut / Modality Shortcut）**
    - 核心定义：模型学会忽略图像，仅凭语言先验和数据共现「猜」答案
    - 典型表现：闭眼答也对——把图遮住，模型仍能给出正确答案
    - 与「对齐失败」的区别
      - 对齐失败：模型「看到图像但读不懂」，视觉 token 没接入语义空间
      - 模态捷径：对齐看似成功，视觉 token 接入了，但模型选择不依赖它
      - 后者更隐蔽、更常见，是「对齐之后」才会浮出来的失效
    - 后果
      - 多模态成绩注水：benchmark 分数虚高，实际不看图也能做对
      - 泛化差：遇到语言先验不覆盖的场景就崩
    - 检测方法
      - **Blind-baseline 对照**：同题报告原图/遮图/错配图成绩及逐题变化；差值是诊断指标，不是“真实多模态能力”或视觉贡献的无偏估计
      - **语言先验惩罚**：构造语言先验与实际图像矛盾的样本，看模型是否被图像纠正
      - **视觉依赖度过滤**：筛选出真正需要看图才能答对的样本
      - **反事实图像扰动**：改一下图，看答案该变的有没有变
    - 缓解手段
      - 数据层面：增加视觉依赖度高的训练样本
      - 训练层面：若引入视觉依赖或对比目标，先验证标注与消融；文字本身可回答的题不应因答对就被惩罚
      - 评估层面：图文任务报告适用的 blind-baseline 与扰动对照，并保留分项和失败样本
  - **视觉幻觉（Object Hallucination）**
    - 核心定义：模型描述图里根本没有的物体
    - 典型表现：图中只有一只猫，模型描述「猫和狗在玩耍」
    - 是 VLM 的头号质量问题
    - 成因分析（三者混合，不是单一根因）
      - 视觉编码器分辨率不足：小物体、细节信息丢失
      - 模态对齐不充分：视觉 token 与文本语义没完全对齐
      - LLM 语言先验过强：模型根据「常见场景」补全不存在的物体
    - 与模态捷径的关系
      - 模态捷径是「绕过视觉」
      - 视觉幻觉是「视觉信息不足时，语言先验补全了错误内容」
      - 两者相关但不同：一个是不看，一个是看了但补错
    - 评估基准
      - **POPE**：用 yes/no 问题检测物体幻觉
      - **HallusionBench**：综合幻觉评估
      - **MMHal-Bench**：多模态幻觉基准
    - 缓解手段
      - 提高视觉分辨率
      - 强化模态对齐训练
      - 降低语言先验的权重（如对比解码）
      - 幻觉检测后处理
    - 范式天花板指针
      - 视觉幻觉有一部分踩在「真值缺失」这条范式天花板上
      - 纯工程手段能缓解，但不能根治
      - 读者需知：不是所有幻觉都是工程债
  - **感知瓶颈论断**
    - 待验证假设：特定任务的失败可能源于视觉特征丢信息；不能由总体分数宣称“问题只在看、不在想”
    - 严格表述
      - 视觉特征丢信息确实是重要瓶颈
      - 但不是唯一根因：模态对齐不充分、语言先验过强也贡献
      - 写作时不要把「感知瓶颈」写成唯一根因
    - 实践意义
      - blind-baseline 高：先检查题目是否依赖图像、答案分布和数据泄漏，不直接判定视觉 encoder 有问题
      - 对视觉必需题，再分别消融分辨率/encoder、processor、连接器与语言侧策略，按逐题证据归因

### 3.3 多阶段 recipe 【多模态独有】

以下沿用第二章的连接器优先示例。复用已训练 VLM、联合预训练或不同架构可省略/合并阶段；不是标准生产配方。

- 阶段 1：模态对齐
  - 数据：图文对
  - 冻结：ViT + LLM
  - 训练：projector
  - 目标：视觉 token 与文本语义对齐
- 阶段 2：多模态预训练
  - 数据：图文对 + 交错图文 + 视频
  - 冻结：此示例冻结 ViT，解冻 LLM
  - 训练：projector + LLM
  - 目标：跨模态理解能力
- 阶段 3：多模态 SFT
  - 数据：多模态指令-回答对
  - 冻结：全解冻或部分解冻
  - 训练：全参数或 LoRA
  - 目标：指令遵循
- 阶段 4：多模态对齐（可选）
  - 数据：多模态偏好数据
  - 方法：RLHF / DPO / GRPO 【共享】
  - 目标：符合人类偏好
- 每阶段的数据、冻结配方、学习率
  - 列出视觉侧、连接器、语言侧的 trainable 参数和各自学习率；随机初始化的 projector 未必使用比预训练 LLM 更小的学习率
  - 配方记录数据版本、有效 token、目标/mask、优化器、冻结表与验证集，不以“小/中学习率”替代可复现配置
  - 偏好优化另记录奖励/偏好规则、采样预算和参考模型；按验证集比较，不存在通用“RLHF 标准配置”

### 3.4 视觉 token 压缩与分辨率策略 【多模态独有】

- 核心问题：视觉 token 爆炸
  - 一张 336×336 图像，patch size 14，产生 576 个 token
  - 一张 1024×1024 图像，产生 5184 个 token
  - 高分辨率图像 + 视频，token 数量爆炸
- 视觉 token 压缩
  - 池化：平均池化或最大池化，简单但损失信息
  - 卷积下采样：用卷积做空间下采样
  - Perceiver Resampler：注意力重采样，压缩比可调
  - Q-Former：可学习 query 提取，压缩比高
  - Token Merging：合并相似 token
- 分辨率策略
  - 固定分辨率：所有图像缩放到固定尺寸，简单但损失细节
  - 动态分辨率：按图像原始比例和尺寸处理，保留细节
  - AnyRes：把高分辨率图像切成多个 patch，分别编码后拼接
  - 采用者：Qwen2-VL 的动态分辨率、LLaVA-NeXT 的 AnyRes
- **【新增】长视频的 token 处理与时间压缩**
  - 核心问题：分钟/小时级视频，抽帧后 token 数量爆炸
  - 时间压缩手段
    - **关键帧抽取**：只保留信息量大的帧，跳过冗余帧
    - **时间池化**：相邻帧特征做时间维度池化
    - **层次化编码**：先编码短片段，再编码片段间关系
    - **视频 tokenizer**：专门为视频设计的 tokenizer，压缩时空维度
  - 与单图 token 压缩的区别
    - 单图：压缩空间维度（H×W）
    - 视频：压缩时空维度（T×H×W），量级更大
  - 工程要点：长视频必须做时间压缩，否则 token 数量无法接受
- 与 LLM 长上下文的关系
  - 视觉 token 压缩是 VLM 特有的显存/算力问题
  - 与 LLM 卷的「长上下文」是两条独立战线
  - 但两者共享序列并行等训练侧技术 【共享】
- 工程权衡
  - 压缩比越高，视觉 token 越少，但信息损失越多
  - 分辨率越高，细节保留越好，但 token 越多
  - 需要按任务类型权衡：OCR 需要高分辨率，通用理解可以压缩

### 3.5 多模态数据工程 【多模态独有】

- 图文对
  - 来源：LAION、DataComp、内部数据
  - 规模：区分候选数据池、过滤后训练集与实际采样量；按视觉预训练/连接器适配/指令任务分别记录，不把公开数据池规模当训练门槛
  - 质量：图文匹配度、清晰度、去重
- **【新增】Re-captioning（重写 caption）**
  - 核心问题：原始 alt-text 噪声大、信息稀
    - 网页 alt-text：短、模糊、SEO 导向，不是好的训练信号
    - 直接吃原始图文对，模型学到的是「弱标签」
  - 核心操作：用 VLM/LLM 给图像重写详细 caption
    - 输入：图像 + 原始 alt-text（可选）
    - 输出：详细、准确、信息密集的 caption
    - 工具：GPT-4V、LLaVA、内部 VLM
  - 代表方案
    - **ShareGPT4V**：用 GPT-4V 重写，构建高质量图文数据集
    - **LLaVA-1.5**：用合成数据 + re-captioning
    - **MM1**：caption 改写，提升图文对质量
  - 与 CLIP 分数过滤的区别
    - CLIP 分数过滤：筛掉差的（筛选）
    - Re-captioning：造出好的（生成）
    - 两者是不同量级的数据操作，可以组合使用
  - 工程要点
    - Re-captioning 成本高，要按数据量权衡
    - 重写后的 caption 要人工抽检，防止 VLM 幻觉引入新错误
    - 可以分级：核心数据用 GPT-4V，长尾数据用开源 VLM
- OCR 数据
  - 用途：文档理解、图表问答
  - 来源：PDF、扫描件、合成数据
  - 标注：文本内容 + 位置 + 版面结构
- Grounding 数据
  - 用途：视觉定位、区域描述
  - 标注：bbox + 文本描述
  - 来源：RefCOCO、Visual Genome
- 交错图文（Interleaved）
  - 用途：多图理解、图文混合对话
  - 形式：文本中穿插图像，如网页、教程
  - 来源：OBELICS、MMC4
- 视频数据
  - 抽帧：均匀抽帧或关键帧抽取
  - 时序标注：动作、事件、时间戳
  - 来源：WebVid、HowTo100M
- 音视频对齐
  - 用途：视频理解、语音识别
  - 标注：音频转写 + 时间对齐
  - 来源：YouTube、内部数据
- 数据质量评估
  - 图文匹配度：CLIP 分数过滤
  - 清晰度：分辨率、模糊度
  - 去重：图像去重 + 文本去重
  - 安全：NSFW 过滤、PII 脱敏 【共享】
- 与纯文本数据工程的关系
  - 共享：去重、质量过滤、数据版本化、合规审计 【共享】
  - 独有：图文匹配、分辨率处理、视频抽帧、模态对齐、re-captioning

### 3.6 多模态分布式训练 【共享 + 多模态独有】

- 并行策略 【共享】
  - 数据并行、张量并行、流水线并行、专家并行、序列并行
  - 见[LLM 训练：分布式训练与显存优化](LLM训练知识体系.md#37-分布式训练与显存优化)
- 视觉 encoder 的并行特殊性 【多模态独有】
  - ViT 通常比 LLM 小，可以放在单卡或少量卡上
  - 视觉 token 数量大时，序列并行对视觉侧也适用
  - 视觉 encoder 和 LLM 可以分别用不同的并行策略
- 模态间通信 【多模态独有】
  - 视觉 token 从 ViT 传到 LLM 需要跨卡通信
  - 如果 ViT 和 LLM 在不同卡上，projector 的输出需要 all-gather 或 all-to-all
  - 工程要点：尽量让 ViT 和 LLM 在同一组卡上，减少跨模态通信
- 显存优化 【共享】
  - ZeRO、梯度检查点、混合精度、FP8
  - 见[LLM 训练：分布式训练与显存优化](LLM训练知识体系.md#37-分布式训练与显存优化)
- 序列并行 【共享 + 多模态独有】
  - Ring Attention、Ulysses 等 【共享】
  - 多模态独有：视觉 token 和文本 token 可以一起做序列并行
  - 工程要点：视觉 token 的序列并行需要特殊处理位置编码（见 3.4）

### 3.7 多模态 SFT 与对齐 【共享 + 多模态独有】

- 多模态 SFT
  - 数据：多模态指令-回答对
  - 训练：与纯文本 SFT 相同 【共享】
  - 多模态独有
    - 数据构造：图文混合指令、OCR 指令、grounding 指令
    - 格式：图像 token + 文本 token 混合序列
    - 只对 assistant 回复计算 loss 【共享】
- 多模态对齐
  - 方法：RLHF / DPO / GRPO 【共享】
  - 多模态独有
    - 偏好数据：多模态偏好对（图像 + 文本 + 两个回答）
    - 奖励模型：需要处理多模态输入
    - 评估：多模态偏好胜率
- **【新增】多模态 RL 的 rollout 特殊性**
  - 核心问题：图像进 rollout 引擎的预处理一致性
    - 训练侧 resize：按训练 recipe 做 resize
    - rollout 侧 resize：按当前策略的有效输入配置，不盲用引擎默认
    - 两者不一致 → 视觉 token 错位 → logprob 偏差 → importance sampling 失效
  - 与 LLM 卷 RL 系统的关系
    - LLM 卷讲的是「训练-推理数值一致性」（logprob 偏差）
    - 多模态多了一层「视觉预处理一致性」（resize 偏差）
    - 两者叠加，问题更复杂
  - 工程要点
    - rollout 与训练 logprob 重算使用相同样本的有效视觉输入；部署遵循发布的 processor，训练随机增强不直接搬到推理
    - resize 的插值方法、目标尺寸、padding 策略都要对齐
    - rollout 与训练重算绑定相同 processor/视觉输入；随机增强结果需一致或可追溯，不能重新随机取另一张有效图
- 多模态 RL 的其他特殊挑战
  - 奖励信号：视觉任务的奖励比文本更难定义
  - 探索空间：视觉输出的探索空间更大
  - 评估：多模态评估成本更高

## 四、多模态 vs 纯文本训练

- 本质区别

  - 多模态：多模态输入，四阶段流水线（多一步模态对齐）
  - 更深差异：多模态有「模态捷径」这一独有失效模式 【新增】
- 共享部分 【共享】
  - 自回归预训练目标
  - SFT 流程
  - RLHF / DPO / GRPO
  - DP / TP / PP / EP / 序列并行
  - ZeRO / 梯度检查点 / 混合精度 / FP8
  - 数据工程方法论（去重、质量过滤、版本化、合规）
  - 评估框架
- 多模态独有部分 【多模态独有】
  - 视觉 encoder 选型与挂载
  - 模态对齐预训练
  - 四阶段 recipe
  - 视觉 token 压缩与分辨率策略
  - 多模态数据工程（图文对、OCR、grounding、交错图文、视频、re-captioning）
  - 多模态能力与评估
  - 原生统一多模态
  - 模态捷径与视觉幻觉 【新增】
- 选型判断
  - 只需要文本能力 → 纯文本 LLM
  - 需要图文理解 → 外挂式 VLM
  - 需要原生多模态 → 统一多模态模型
  - 需要视频理解 → 视频 VLM
  - 需要具身智能 → VLA

## 五、高级多模态范式 【多模态独有】

- 原生统一多模态（Early Fusion）
  - 核心：图像被 tokenize 进统一序列，与文本 token 一起训练
  - 代表：GPT-4o、Gemini、Chameleon、Emu3、Janus
  - 与 late fusion 的区别
    - Late fusion：外挂视觉 encoder，视觉和文本分开处理
    - Early fusion：统一 tokenize，视觉和文本在同一个序列里
  - 优势：模态融合更彻底，支持任意模态组合
  - 劣势：训练成本高，需要大规模多模态数据
  - 趋势判断：early fusion 是未来方向，两套体系最终会合并
  - **【新增】图像离散化（Image Tokenizer）**
    - 核心问题：图像是连续的，怎么变成离散 token 进统一序列
    - 主流方法
      - **VQ-VAE / VQGAN**：用向量量化把图像编码为离散码本
        - 核心：学习一个码本（codebook），每个图像 patch 映射到最近的码字
        - 优势：离散化彻底，与文本 token 同构
        - 劣势：码本大小受限，重建质量有损
      - **FSQ（Finite Scalar Quantization）**：有限标量量化；不要与 MAGVIT-v2 的 LFQ（Lookup-Free Quantization）混为一谈，见[MAGVIT-v2 原论文](https://arxiv.org/abs/2310.05737)
        - 核心：用有限标量量化替代向量量化，训练更稳定
        - 优势：无需码本学习，训练简单
      - **连续表示 vs 离散表示之争**
        - 离散：与文本同构，可直接进 LLM，但重建有损
        - 连续：重建质量高，但与文本 token 不同构，需要额外处理
        - 当前趋势：离散表示是 early-fusion 主流
    - 工程要点：图像 tokenizer 质量直接决定 early-fusion 的上限
  - **【新增】二维 / 多模态位置编码（2D-RoPE / M-RoPE）**
    - 核心问题：图像 patch 是 2D 的（还有视频是 t/h/w 三维），一维 RoPE 不够用
    - 主流方法
      - **2D-RoPE**：把位置拆成 height 和 width 两个维度，分别编码
      - **M-RoPE（Multimodal RoPE）**：Qwen2-VL 使用，把时间/高/宽拆开编码
        - 时间维度：视频帧间位置
        - 高度维度：图像行位置
        - 宽度维度：图像列位置
    - 解决的问题
      - 「多图/视频里哪个 token 属于哪块」的归属问题
      - 显式编码 2D/3D 结构可改善空间/时间位置建模；一维排列仍可结合视觉特征表达空间信息，不断言绝对无法表达
    - 工程要点
      - M-RoPE 是 Qwen2-VL 的核心创新之一
      - 并行切片时必须保留该模型实际采用的位置索引；有些模型使用一维位置编码，不强制所有架构改成 2D/M-RoPE
  - **【新增】理解↔生成互斥（Janus 的 conflict）**
    - 核心问题：统一模型里，理解任务和生成任务的目标互相拉扯
    - 具体表现
      - 理解任务：需要语义抽象的特征
      - 生成任务：需要像素级细节的特征
      - 两者对视觉 encoder 的要求不同
    - Janus 的解法
      - 解耦视觉编码：理解用一套，生成用另一套
      - 统一在 LLM 主干上
    - 工程意义：统一多模态不是简单「把图像 tokenize 进序列」，还有目标冲突要解决
- 扩散 + 自回归混合
  - 核心：文本用自回归目标，图像用扩散目标
  - 代表：[Transfusion](https://arxiv.org/abs/2408.11039)
  - 挑战：不同模态的训练目标和生成过程如何协调
- 纯自回归统一
  - 代表：[Emu3](https://arxiv.org/abs/2409.18869)：将文本、图像、视频表示为离散 token，以 next-token prediction 统一理解与生成，不是扩散混合模型
- 视频多模态
  - 核心：视频理解需要时序建模
  - 方法：抽帧 + 时序编码、视频 tokenizer
  - 代表：Video-LLaVA、Qwen2-VL 视频版
- 音频多模态
  - 核心：音频理解 + 语音识别 + 音频生成
  - 方法：音频 encoder + 模态对齐
  - 代表：Qwen-Audio、GPT-4o 语音版
- VLA（Vision-Language-Action）
  - 核心：视觉 + 语言 + 动作，用于机器人控制
  - 方法：视觉 encoder + LLM + 动作头
  - 代表：RT-2、OpenVLA
- 具身多模态
  - 核心：多模态感知 + 物理世界交互
  - 挑战：实时性、安全性、物理世界不确定性

## 六、多模态安全与对齐 【共享 + 多模态独有】

- 共享部分 【共享】
  - 提示注入防御
  - 不可逆操作确认
  - 沙箱与隔离
  - 见 Agent 卷第六章
- 多模态独有 【多模态独有】
  - 视觉提示注入：恶意指令藏在图像里
    - 形式：图像中的文字、隐写术、对抗扰动
    - 危害：模型可能执行图像中的恶意指令
    - 防御：图像内容检测、OCR 过滤、对抗训练
  - NSFW 内容过滤：图像 + 文本双重过滤
  - 深度伪造检测：生成图像/视频的检测
  - 隐私保护：图像中的人脸、车牌、PII 脱敏
  - 版权：训练图像的版权合规 【共享，见 LLM 卷 3.1】
  - **【新增】视觉幻觉作为独有安全风险**
    - 核心问题：模型描述不存在的物体，误导用户
    - 与文本幻觉的区别
      - 文本幻觉：模型编造事实
      - 视觉幻觉：模型编造视觉内容，用户更容易相信（「眼见为实」）
    - 危害场景
      - 医疗影像：描述不存在的病灶
      - 安防监控：描述不存在的物体或事件
      - 文档理解：读出文档里没有的内容
    - 防御
      - 反幻觉评估（POPE、HallusionBench）
      - 对比解码
      - 幻觉检测后处理
    - 范式天花板指针
      - 视觉幻觉有一部分踩在「真值缺失」这条范式天花板上
      - 纯工程手段能缓解，但不能根治
      - 读者需知：不是所有幻觉都是工程债
- 多模态对齐的特殊挑战
  - 偏好数据：多模态偏好对更难标注
  - 奖励模型：需要处理多模态输入
  - 评估：多模态评估成本更高
  - 安全：视觉内容的危害更难定义

## 七、多模态效果评估 【多模态独有】

- 视觉理解
  - 图像分类：ImageNet zero-shot
  - 图像描述：CIDEr、SPICE
  - 视觉问答：VQAv2、GQA
  - 视觉定位：RefCOCO、Visual Genome
- 文档理解
  - OCR：OCRBench
  - 文档问答：DocVQA、InfographicVQA
  - 表格理解：TableVQA
- 多模态推理
  - MMMU：多学科多模态理解
  - MathVista：数学视觉推理
  - MMBench：综合多模态能力
- **【新增】反幻觉评测**
  - POPE：用 yes/no 问题检测物体幻觉
  - HallusionBench：综合幻觉评估
  - MMHal-Bench：多模态幻觉基准
  - 核心：专门测「描述不存在的物体」这类失效
  - 与通用 benchmark 的区别：通用 benchmark 测能力，反幻觉 benchmark 测失效
- 视频理解
  - 视频问答：MSVD-QA、MSRVTT-QA
  - 视频描述：VideoCIDEr
  - 时序定位：ActivityNet
- 音频理解
  - 语音识别：LibriSpeech 是数据集，WER 是错误率指标，说明测试子集和文本归一化协议
  - 音频描述：AudioCaps 提供音频与描述文本，不是通用问答基准。见[原论文（2019）](https://aclanthology.org/N19-1011/)
  - 音频问答：另选有问题/答案标注的数据与评分协议，不能用 caption 成绩代替问答能力
- 生成评估
  - 图像生成：FID、CLIP Score
  - 视频生成：FVD
  - 多模态生成：人工评估 + LLM-as-judge 【共享】
- 评估可靠性 【共享 + 多模态独有】
  - LLM-as-judge 偏差 【共享】
  - 数据污染 【共享】
  - **【新增】Benchmark 的视觉依赖度**
    - 核心问题：既然模型能绕过图走语言捷径，那「考多模态的 benchmark」很可能不看图也能做对
    - 检测方法
      - **Visual-dependency 过滤**：筛选出真正依赖视觉的题目
      - **反事实图像扰动**：改一下图，看答案该变的有没有变
      - **Blind-baseline 对照**：报告看图/遮图/错配图的分项与差值；简单相减不等于真实视觉能力
    - 与模态捷径的关系
      - 模态捷径是「模型绕过视觉」
      - 视觉依赖度是「benchmark 能否检测出模型绕过了视觉」
      - 两者是一对：没有视觉依赖度检测，就发现不了模态捷径
    - 工程要点
      - 评估视觉贡献时报告适用的 blind-baseline 与扰动对照；无法构造有效对照时说明限制，不伪造可比性
      - 只报原始分数会掩盖模态捷径问题
  - 多模态独有：视觉评估的标注成本更高

## 八、多模态成本与算力工程 【多模态独有】

- 多模态训练的算力特点
  - 视觉 encoder：是否训练、参数量、分辨率和数据规模决定开销；复用冻结视觉塔不产生其从零预训练成本
  - 连接器适配、联合预训练、SFT 与偏好优化：分别估算有效 token、可训练参数、训练步数与 rollout，不使用固定“小/中/大”排序
- 视觉 token 的算力影响
  - 视觉 token 数量直接影响序列长度
  - 序列长度直接影响注意力计算量
  - 压缩视觉 token 是降低算力的关键
  - 长视频的时间压缩是额外算力优化点 【新增】
- 数据成本
  - 图文对数据：采集 + 清洗 + 标注 + re-captioning 【新增】
  - 视频数据：抽帧 + 时序标注
  - OCR 数据：文档采集 + 标注
- 成本构成
  - 数据获取/授权/清洗、视觉侧训练或权重复用、连接器与语言侧训练、评测及偏好采样
  - 先列出实际执行的阶段和冻结表；既有模型接入不能重复计入别人已完成的预训练，重训也不是固定一次性成本
- 与纯文本训练的成本对比
  - 只有在模型起点、数据/token 预算、硬件与目标相近时比较；不存在所有多模态训练都比所有纯文本训练昂贵的结论
  - 多模态额外开销常来自视觉处理与 token、数据工程；压缩或冻结策略收益需与质量损失一起验收

## 十、多模态落地工程难点 【多模态独有】

- 视觉 encoder 与 LLM 的对齐：对齐不好，模型「看到图像但读不懂」
- **模态捷径：对齐看似成功，模型仍可能绕过视觉** 【新增】
- **视觉幻觉：描述不存在的物体，是 VLM 头号质量问题** 【新增】
- 视觉 token 爆炸：高分辨率 + 视频导致 token 数量爆炸
- 长视频时间压缩：分钟/小时级视频的 token 处理 【新增】
- 多模态数据质量：图文匹配度、分辨率、去重都比纯文本难
- **Re-captioning 成本高：用 VLM/LLM 重写 caption 的成本要权衡** 【新增】
- 模态间通信：ViT 和 LLM 跨卡通信是独立工程难题
- 多模态对齐：RLHF 在多模态上的成本更高
- **多模态 RL rollout：训练侧和推理侧 resize 不一致导致视觉 token 错位** 【新增】
- 视觉提示注入：图像中的恶意指令是新型攻击面
- 评估成本：多模态评估的标注成本远高于纯文本
- **Benchmark 视觉依赖度：不报告 blind-baseline 会掩盖模态捷径** 【新增】
- 核心认知：多模态增加表示、预处理和跨模态证据约束；主要瓶颈随任务与训练起点变化，不预设对齐总是最大门槛

### 10.1 多模态训练常见反模式 【多模态独有】

- 不验证表示兼容与训练配方
  - 表现：不检查已有表示、连接器与目标就照搬其他模型的阶段或拼接权重
  - 后果：可能引入表示不兼容、无效训练或能力退化；跳过独立 Phase 1 本身不必然是错误
  - 正解：对齐是目标，不一定是独立必经阶段；按已有 encoder、架构与数据评估联合训练或分阶段训练
- 视觉 token 不压缩直接塞进 LLM
  - 表现：高分辨率图像不压缩，几万 token 塞进上下文
  - 后果：显存爆炸，训练和推理都跑不动
  - 正解：用池化、Q-Former、Resampler 压缩视觉 token
- 冻结策略一刀切
  - 表现：所有阶段都用同一冻结策略
  - 后果：要么训练不充分，要么成本过高
  - 正解：分阶段解冻，先冻后解
- 多模态数据不做图文匹配过滤
  - 表现：直接用原始图文对，不做 CLIP 分数过滤
  - 后果：噪声数据教坏模型
  - 正解：用 CLIP 分数过滤低质量图文对
- **【新增】只做 CLIP 过滤不做 Re-captioning**
  - 表现：只筛掉差的，不造出好的
  - 后果：数据质量上限被原始 alt-text 卡住
  - 正解：CLIP 过滤 + Re-captioning 组合使用
- 忽略视觉提示注入
  - 表现：只做文本提示注入防御，不做图像内容检测
  - 后果：图像中的恶意指令被模型执行
  - 正解：图像内容检测 + OCR 过滤 + 对抗训练
- 视觉 encoder 和 LLM 并行策略不匹配
  - 表现：两者用相同的并行策略
  - 后果：通信开销大，扩展性差
  - 正解：视觉 encoder 和 LLM 可以分别用不同的并行策略
- 不做多模态评估只做文本评估
  - 表现：用文本 benchmark 评估多模态模型
  - 后果：无法发现视觉能力的缺陷
  - 正解：用 MMMU、MathVista、MMBench 等多模态基准
- **【新增】不检测模态捷径**
  - 表现：只看 benchmark 分数，不看 blind-baseline
  - 后果：分数虚高，模型实际不看图也能答对
  - 正解：报告 blind-baseline 与反事实图对照，差值不是通用的真实视觉能力分数
- **【新增】不做反幻觉评估**
  - 表现：只测通用 benchmark，不测幻觉
  - 后果：模型描述不存在的物体，用户被误导
  - 正解：用 POPE、HallusionBench、MMHal-Bench 专门测幻觉
- **【新增】多模态 RL 不做视觉预处理一致性校验**
  - 表现：训练侧和推理侧 resize 不一致
  - 后果：视觉 token 错位，importance sampling 失效
  - 正解：固定发布 processor，并验证 rollout 与 logprob 重算的有效输入一致
- **【新增】Early-Fusion 不考虑理解↔生成互斥**
  - 表现：直接把图像 tokenize 进序列，不做目标解耦
  - 后果：理解任务和生成任务互相拉扯，两边都不好
  - 正解：参考 Janus，解耦视觉编码

## 范围、衔接与验收

视觉语言是本卷主线；语音需另补音频表示、ASR/TTS、流式打断与 WER/CER，生成需补扩散/自回归目标及评价，VLA 需补动作表示、环境闭环与安全约束。列出名称不等于完整覆盖分支。

推理使用随模型发布的 tokenizer/processor、图像 patch 与位置规则，训练随机增强不要求原样搬到推理。用原图、遮图、错配图对照验证视觉依赖，避免纯文字就能答的题冒充视觉能力。共享评测与版本要求见[评测方法](评测与实验方法.md)和[生命周期](模型全生命周期闭环知识体系.md)。

编码器实例依据：[SigLIP（2023）](https://arxiv.org/abs/2303.15343)、[PaliGemma 的 SigLIP 视觉塔（2024）](https://arxiv.org/abs/2407.07726)。模型实例归属不推广至该系列全部版本。
