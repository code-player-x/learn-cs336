## 二、掌握标准

每个专题按四层验收：能解释原理 → 能跑最小例子 → 能分析失败 → 能提供可复现证据。读过术语、运行 Demo 不等于掌握生产能力。

专题前读共同基础；优化前固定评测集与基线；改动后交付版本、结果和失败样本。安全、权限、成本、评测贯穿各卷。

已有 CS336 笔记负责原理与实现，入口为[课程总览](../00-课程总览与学习路线.md)；本目录负责工程知识地图与验收衔接，避免重复整本教材。

## 三、证据与维护规则

- 算法优先引用原论文；API、硬件、框架优先引用官方文档，实验记录实际版本。
- 性能、价格、数据规模注明模型、数据、硬件、精度、负载、基线与日期。缺少条件的数字不作为工程结论。
- 示例阈值不冒充行业标准；实验收益不冒充普遍保证；未知事项写“待验证”。
- 实验关联数据版本、配置、代码提交和结果文件。合成数据、LLM 评分、用户纠正均需校准或抽检。
- 模型、索引、权限、工具或引擎变更触发回归；权限撤销和数据删除不能靠回滚旧快照处理。

各卷给出关键纠错的依据链接，不代表所有模型、工具与版本都获逐项认证；正式选型仍需查相应版本并实测。

## 四、专题深度与更新合同

核心主题按“原理 → 适用条件 → 失败模式 → 验收方法”展开；只列算法/工具名称的条目是检索入口或选修指针，不视为已掌握。

| 内容类型 | 应标注的信息 | 不能推出的结论 |
| --- | --- | --- |
| 稳定原理 | 定义、假设、适用边界与原始依据 | 理想假设下的推导不保证实际模型行为 |
| 历史论文实例 | 模型/方法的确切版本、年份、原论文与实验条件 | 某版本采用的组件不代表整个系列都采用 |
| 当前工程建议 | 核实日期、官方维护/支持状态、目标负载与待验证项 | 工具名字、流行度不证明性能或生产适用性 |

更新时检索并同步旧段落、选型摘要、反模式与学习路线；交叉引用使用章节链接，不仅写裸编号。若结论仍未核实，标为“待验证”，不把修订日期当逐项认证。

[最小验收示例](最小验收示例.md)验证引用与 mock 行动规则；[端到端 RAG 案例](端到端RAG教学案例.md)进一步提供真实文件处理/检索、离线摘录基线和可选模型 HTTP 接口。固定样本和本地协议测试不证明真实模型质量、生产 RAG/Agent 能力或 GPU 性能，仍按[实践清单](实践与验收清单.md)另行验收。
