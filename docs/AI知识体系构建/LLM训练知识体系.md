# LLM 训练完整知识体系

> 本卷面向文本大模型训练工程。先修见[基础与模型原理](基础与模型原理.md)，实验与验收见[评测方法](评测与实验方法.md)、[实践清单](实践与验收清单.md)；返回[总索引](README.md)。

## 一、LLM 训练基础认知

- 核心定义
  - 全称：大语言模型训练（Large Language Model Training）
  - 核心解决：让模型从「随机权重」变成「能理解、能生成、能对齐人类意图」的通用智能体
  - 本质：通过海量数据和算力，把语言知识和推理能力「压缩」进模型参数
- 与推理的本质区别
  - 推理：输入 → 输出，模型参数冻结，自回归生成通常包含 prefill 和多步 decode
  - 训练：前向传播 + 反向传播 + 参数更新，多轮迭代，参数持续变化
- 三大核心阶段
  - 预训练（Pre-training）：海量文本上学习语言和世界知识
  - 指令微调（SFT）：用指令-回答数据教会模型「听懂人话」
  - 对齐（Alignment）：用人类偏好让模型「说人想听的话」
- 核心价值
  - 能力注入：把知识、语言、推理能力写进参数
  - 行为塑造：让模型遵循指令、拒绝不当请求、输出符合人类偏好
  - 领域适配：通过微调让通用模型适配垂直领域
- 文档定位声明
  - 本文档定位纯训练工程视角
  - 不含能力边界/哲学讨论（意向性、持续学习不可能、真值缺失等属于 AI 哲学范畴，不在工程体系内）
  - 不含多模态训练（视觉 encoder 挂载、模态对齐等属于独立专题卷）
  - 不含推理部署（量化、KV Cache、推理引擎等属于推理部署体系）
  - 存在一条范式天花板讨论，不在本卷范围内，读者需知工程体系不等于模型认知的全貌

## 二、LLM 训练完整工作流程

- 常见三阶段配方（不是必选流水线）
  - Phase 1：预训练（Pre-training）
    - 目标：学习通用语言理解与生成能力
    - 数据：大规模文本语料（规模按模型、质量和算力预算设计）
    - 方法：自监督学习，Next-Token Prediction
    - 产出：Base Model（有知识、能续写，但不会「对话」）
  - Phase 2：监督微调（SFT / Instruction Tuning）
    - 目标：教会模型遵循指令、以对话格式回答
    - 数据：有授权的高质量指令-回答对（规模按任务验证）
    - 方法：在指令数据上做监督学习
    - 产出：Instruct Model（能对话、能执行任务）
  - Phase 3：对齐（Alignment / RLHF / DPO / GRPO）
    - 目标：让模型输出符合人类偏好、安全、有用
    - 数据：人类偏好数据（pairwise comparisons）或可验证奖励
    - 方法：强化学习或直接偏好优化
    - 产出：Aligned Model（最终部署版本）
- 关键认知
  - 预训练提供「地基」，后训练决定「建成什么楼」
  - 后训练显著影响指令遵循和行为，能力仍受基座、数据、任务与预算共同约束
  - 阶段取舍取决于起点和目标，不要求全部执行；DeepSeek-R1-Zero 展示了不先做 SFT 的 RL 路径，见[论文](https://arxiv.org/abs/2501.12948v1)

### 2.1 预训练（Pre-training）完整流程

- Step 1：数据收集
  - 主要来源：网页（Common Crawl）、书籍、论文（arXiv/PubMed）、代码（GitHub）、对话数据
  - 数据规模：GPT-3 300B tokens；LLaMA 2 2T；LLaMA 3 15T；DeepSeek V3 14.8T；Qwen 3 36T
- Step 2：数据预处理
  - 清洗步骤：去重、质量过滤、毒性移除、语言识别、PII 减少
  - 数据混合策略：按质量与多样性分配采样权重，而非均匀采样
  - 质量评估维度：表达清晰度、结构完整性、内容可信度、知识丰富度、逻辑深度
- Step 3：分词（Tokenization）
  - 子词算法：BPE（GPT 系列）、WordPiece（BERT）、Unigram（SentencePiece）
  - 词表大小：32K-200K，LLaMA 3 使用 128K
  - Tokenizer 质量对能力的隐性影响
    - 核心认知：分词器与词表、嵌入和输出头紧密耦合，属于高迁移成本的结构性决策
    - 非拉丁语系的 token 膨胀
      - 现象：同一段中文，用英文分词器可能比用中文优化分词器多出 2-3 倍 token
      - 后果：直接抬高训练和推理成本、稀释有效上下文窗口、降低中文任务表现
      - 工程要点：中文/日文/韩文等非拉丁语系必须有专门的分词优化
    - 数字与代码的分词方式
      - 现象：数字按位（1, 2, 3）vs 按段（123）分词，对算术能力影响显著
      - 代码：缩进、符号、关键字的分词方式影响代码生成质量
      - 工程要点：分词器设计时要做下游任务验证，不能只看压缩率
    - 分词决策的迁移成本
      - 词表一旦确定，所有预训练数据都要按它切
      - 扩词表或迁移分词器需处理 token ID、嵌入、输出头和数据，并做继续训练与回归；不必然从零全部重训
      - 工程要点：分词器设计要在预训练开始前充分验证
- Step 4：模型架构选择
  - Decoder-only（GPT 风格）为主流
  - 关键超参：层数、隐藏维度、Q/KV 头数、上下文长度；范围由具体模型与资源决定
- Step 5：预训练目标
  - 自回归语言建模：Next-Token Prediction
  - 损失函数：负对数似然 $\mathcal{L}(\theta) = -\sum \log P(x_t|x_{<t};\theta)$
  - 变体：因果掩码（左到右）、Fill-in-the-Middle（代码模型）
- Step 6：训练优化
  - 优化器：AdamW（主流），Lion / Shampoo / Muon 为新兴选择
  - 学习率：Warmup + Cosine Decay，或 WSD（Warmup-Stable-Decay）
  - 梯度裁剪、混合精度训练（BF16/FP16/FP8）
  - 批量大小：1M-10M tokens
- Step 7：分布式训练
  - 数据并行（Data Parallelism）
  - 张量并行（Tensor Parallelism）
  - 流水线并行（Pipeline Parallelism）
  - 序列/上下文并行（Sequence/Context Parallelism）
  - ZeRO 优化（DeepSpeed）
- Step 8：评估与 Scaling
  - 监控指标：Loss 曲线、Perplexity、下游任务表现
  - Scaling Laws：联合拟合示例 $L(N,D)=E+A/N^\alpha+B/D^\beta$，$N$ 为参数数、$D$ 为训练 token 数；拟合系数与适用范围依赖实验

### 2.2 中期训练 / 退火阶段（Mid-training / Annealing）

- 定位：部分配方在预训练后期调整数据、上下文或学习率，称中期训练/退火；两者不严格同义，也不是所有模型的独立必选阶段
- 核心目标：按下游目标改善能力与数据分布匹配
  - 高质量数据切换、长上下文适配与学习率变化需要消融验证
  - 不能仅凭阶段名称断言模型从「记忆」变成「抽象」
- 关键设计
  - 数据切换：从通用网页数据切到高质量领域数据（数学、代码、指令格式）
  - 学习率退火：从预训练学习率线性衰减到接近 0
  - 上下文扩展：在中期训练阶段做长上下文外推（YaRN/NTK-aware），比从头训练长上下文更高效
- 典型实践
  - OLMo 2：使用 Dolmino Mix 1124 等后期高质量混合配方；这不是 Llama 3 的官方配方，见[OLMo 2 论文](https://arxiv.org/abs/2501.00656)
  - 其他模型也可能调整后期数据和学习率；应逐一查技术报告，不推定相同流程
- 为什么独立
  - 数据分布、学习率策略、评估重点都与标准预训练不同
  - 产出直接决定 SFT 的起点质量
  - 有研究将其视为独立阶段并给出系统化分类

## 三、核心组件详解

### 3.1 数据工程

- 数据收集
  - 来源多样性：网页、书籍、论文、代码、对话
  - 规模与质量权衡：数据质量比规模更重要
- 数据清洗
  - 去重：精确去重 + 模糊去重
  - 质量过滤：基于规则 + 基于模型的评分
  - 毒性移除、PII 脱敏
- 数据混合
  - 传统方法：按领域权重均匀采样
  - 现代方法：按样本质量与多样性分配权重
  - 【深度】自动化混合方法
    - **DoReMi（Domain Reweighting with Minimax Optimization）**
      - 核心目标：最小化各领域上的「最坏情况超额损失」
      - 具体计算流程
        - Step 1：用初始权重训练参考模型（280M）
        - Step 2：用 Group DRO 训练代理模型，动态调整各领域采样权重
        - Step 3：取 DRO 训练过程中领域权重的平均值
        - Step 4：用这些权重训练大模型（8B，30 倍于代理模型）
      - 论文实验：280M 代理与参考模型的权重优化约用 8B 主模型训练算力的 8%；在 The Pile、指定基线下，下游准确率提升 6.5 个百分点、达到基线所需训练步数减少 2.6 倍，不是通用收益。见[DoReMi](https://arxiv.org/abs/2305.10429)
    - **BiMix（Bivariate Data Mixing Law）**
      - 公式：$L_i(r_i, s) = \frac{A_i}{r_i^{\alpha_i}} \left( \frac{B_i}{s^{\beta_i}} + C_i \right)$
      - 直觉：$B_i / s^{\beta_i}$ 捕捉训练步数缩放，$1 / r_i^{\alpha_i}$ 捕捉领域比例缩放，$C_i$ 是拟合项；当 $s$ 增大时该式趋于 $A_i C_i/r_i^{\alpha_i}$，不能把 $C_i$ 本身当作与配比无关的损失下界。见[BiMix](https://arxiv.org/abs/2405.14908)
      - 关键发现：熵驱动的数据混合（特别是条件熵）可达到与计算密集型方法相当甚至更好的效果
  - 动态混合：训练过程中调整数据配比
  - 课程学习 / 数据排序
    - 核心问题：配比决定「喂什么比例」，课程决定「什么顺序喂」，两者是正交维度
    - 课程维度
      - **难度课程**：先易后难，或先难后易
      - **长度课程**：从短序列逐步过渡到长序列
      - **质量课程**：从高质量数据开始，逐步引入更多样数据
    - 典型方法
      - **Length Curriculum**：从小 seq_len 开始，逐步增大，降低初期训练不稳定
      - **Difficulty Curriculum**：按样本难度（如 loss 值）排序，从易到难
      - **Data Ordering**：研究显示数据顺序对收敛速度和终点效果有显著影响
    - 与数据混合的关系
      - 混合：决定「不同来源的比例」
      - 课程：决定「同一来源内部的顺序」
      - 两者正交，可以组合使用
    - 工程要点
      - 课程设计要实验验证，不是理论最优就是实际最优
      - 过长课程可能浪费训练步数，过短可能没效果
- 数据质量评估框架
  - 7 个维度：表达清晰度、完整性、结构、可信度、重要性、知识丰富度、逻辑深度
  - 评分范围：0-10，用于样本级筛选
- 质量过滤的工程校准
  - 核心问题：过滤太狠丢多样性，过滤太松等于没滤
  - 关键认知：质量过滤的本质是「去噪」，不是「找金子」
  - 正确做法：用小规模代理模型做校准实验，确定过滤阈值
- 合成数据（Synthetic Data）
  - 地位：不再是「补充」，而是 SFT 和对齐的重要来源
  - 典型用途
    - 弥补稀缺领域：小语种、专业领域、低资源任务
    - 质量增强：用强模型生成高质量推理链，蒸馏给小模型
    - 规模扩展：PersonaHub 等方案探索 persona 驱动的数据生成；潜在 persona 规模不等于已经生成且验证过的训练样本数
  - 代表数据集：OpenThoughts-114k、Nemotron 系列
  - 风险：模型生成数据的偏差会被继承，需要质量过滤和多样性控制
  - Model Collapse（合成数据自噬）
    - 核心问题：用模型生成的数据反复训练模型，分布尾部塌缩、性能退化
    - 失效机制：第一代数据分布比真实数据窄 → 第二代更窄 → 迭代 N 代尾部消失
    - 两种塌缩模式：早期塌缩（快速丢失尾部，整体性能暂时保持）、晚期塌缩（可能全面退化；能否恢复依赖真实数据、训练过程与评估，不断言不可逆）
    - 防护栏：保留真实数据锚点、控制代际比例、质量过滤、多样性监控
- 数据版本化与数据卡（Dataset Card）
  - 核心：记录来源、清洗步骤、过滤规则、风险评估
  - 目的：可追溯、可审计、可复现
  - 工业级训练管线的标配，合规审计的必需品
  - 版权与授权合规
    - 与 PII 脱敏并列的另一根合规支柱
    - 现实风险：NYT 诉 OpenAI 等诉讼，fair use 争议
    - 数据卡应记录：授权链、版权状态、使用限制、溯源信息
    - 工程要点：数据溯源必须从采集阶段开始记录，授权信息结构化存储

### 3.2 模型架构

- Transformer 核心组件
  - 自注意力（Self-Attention）：$Attention(Q,K,V) = softmax(QK^T/\sqrt{d_k})V$
  - 多头注意力（MHA / MQA / GQA）：MHA 多组 KV，MQA 单组 KV，GQA 折中
  - 位置编码：RoPE（旋转位置编码）为主流
  - 激活函数：SwiGLU / GELU
  - 归一化：LayerNorm / RMSNorm
- Decoder-only 架构
  - 因果掩码（Causal Mask）：保证自回归生成
  - 主流模型：GPT、LLaMA、Qwen、DeepSeek
- MoE（Mixture of Experts）架构
  - 核心设计：总参数大、激活参数小
    - 例子：DeepSeek-V3 总参数 671B，激活参数 37B
  - 核心组件：Router、Experts、Top-K 路由
  - 【深度】MoE 的 auxiliary loss 形式与优缺点
    - 传统 auxiliary loss：$L = L_{model} + \alpha L_a + \beta L_z$，辅助 loss 与主 loss 存在冲突
    - Auxiliary-Loss-Free Load Balancing：根据负载反馈更新路由 bias，而非把该 bias 当普通主 loss 梯度参数；模型仍可能另有小规模序列级辅助 loss
    - Batch-wise auxiliary loss：只在 batch 级别强制均衡
  - 训练侧核心痛点
    - 专家负载不均衡：auxiliary loss、专家容量限制、Router 温度调节、bias 调节
    - All-to-All 通信瓶颈：专家并行、通信压缩、计算通信重叠、动态样本放置
    - 训练不稳定性：Router 冻结策略、分阶段训练、梯度裁剪
  - 与 Dense 架构的权衡：总参数更大 vs 训练复杂度高
  - 主流采用：DeepSeek-V3/R1、Qwen 3、Mixtral、Switch Transformer
- 非 Transformer 架构：SSM 系列
  - Mamba：线性复杂度，长序列有优势
  - 与 Transformer 的关系：重叠但不同的表达容量，混合架构可能更优
  - 当前状态：学术活跃，工业部署仍以 Transformer 为主
- 【深度】长上下文外推（RoPE Scaling）
  - 主要方法：PI、NTK-aware、YaRN、LongRoPE
  - YaRN 的 attention temperature：$\frac{1}{\sqrt{t}} = 0.1 \ln s + 1$
  - LongRoPE 三阶段：4K→256K→2048K→短上下文恢复
  - 关键认知：分频率插值 + 注意力温度校准的组合
- 缩放定律（Scaling Laws）
  - Chinchilla：原论文密集模型、特定计算预算下约每个参数训练 20 个 token；这是经验配方，不是所有数据、架构或推理预算下的普遍最优，见[原论文](https://arxiv.org/abs/2203.15556)
  - 新趋势：小参数 + 超大数据（8B 模型喂 15T token）
  - 涌现能力测量争议：可能是评估指标非线性导致的假象
  - 超参迁移方法论（µP + lr–batch 缩放）
    - µP：按参数角色（输入、隐藏、读出）和优化器分别设初始化、学习率及输出缩放，不能给全部权重套同一个 1/width 规则
    - 目标：在正确参数化与相近配置下改善宽度间超参迁移；仍需 coordinate check 和实测。见[mup 实现](https://github.com/microsoft/mup)
    - lr–batch 缩放：线性缩放（小 batch）、平方根缩放（大 batch）、Critical Batch Size
    - 工具：`mup` 包（Microsoft）

### 3.3 监督微调（SFT）

- 核心目标：教会模型遵循指令、输出对话格式
- 数据构造
  - 指令-回答对
  - 多样性关键：指令多样性带来零样本泛化能力
  - Chain-of-Thought 格式
  - 核心认知：数据质量 > 数量
- 训练细节
  - 只对 assistant 回复计算 loss，mask 掉 prompt token
  - 学习率远低于预训练
  - 数据量：由任务、覆盖度、质量和预算确定，不设统一条数
- SFT 的局限
  - 通过示范间接学习偏好，不直接优化 chosen/rejected 的相对偏好目标
  - 训练数据中的错误会被学习
  - 常见实现对有效 token 等权，也可以按角色、样本或 token 加权

### 3.4 对齐技术（Alignment）

**原理与代码衔接**：先读 [Lesson 18](../18-RLHF-DPO-GRPO对齐技术.md) §1.4–§1.7 的奖励模型、PPO、DPO、GRPO 推导，再对照 §2.1–§2.4 实现与第五部分练习。完成一个目标的手算、有限值/梯度检查和能力退化评测后，再扩展到其他方法；下面的工程清单不替代公式与实现。

- 拒绝采样自训练（RFT）
  - 定位：可选的采样筛选与监督学习路线，不是必经桥梁
  - 流程：生成多个回答 → 奖励模型打分 → 筛最高分 → SFT → 循环
  - 局限：依赖奖励模型或规则验证器质量，也有分布偏移和迭代成本
- RLHF（Reinforcement Learning from Human Feedback）
  - 三阶段：SFT → 奖励模型 → PPO
  - 奖励模型：Bradley-Terry 偏好模型
  - PPO：最大化奖励 - KL 惩罚
  - RL 后训练成本拆解：策略采样 + 评分器推理 + 梯度更新
  - 成本需按采样、评分、更新、硬件时间与单价分别实测，不引用缺少可核查条件的固定金额或占比
- RLAIF
  - 用强模型代替人类标注偏好，大幅降低标注成本
- DPO
  - 在 KL 正则化奖励目标的假设下利用最优策略与隐式奖励关系，直接优化偏好对；标准离线 DPO 更新不需在线 RL 采样或显式奖励模型，但偏好数据采集仍有成本
  - 局限：长度偏差、依赖参考模型、需要成对偏好数据
- 【深度】GRPO
  - 组内归一化：$\hat A_i=(r_i-\bar r)/(\operatorname{std}(r)+\epsilon)$，这里 $\epsilon>0$；全同奖励组优势为 0，标准差口径与实现保持一致
  - 不训练独立 critic，可减少相应状态和计算；总显存收益取决于模型、参考策略、rollout 与实现，不保证减半
  - 采用者：DeepSeek-R1
- 【深度】DAPO
  - Clip-Higher：解耦上界和下界，鼓励探索，防止熵坍缩
  - 四项技术：Clip-Higher、动态采样、Token 级策略梯度损失、超长奖励塑形
- SimPO / KTO / ORPO / RLVR
- RL 训练的探索坍塌（Entropy Collapse）
  - 核心问题：策略熵持续下降，输出多样性消失，奖励停止上涨
  - 与 reward hacking 的区别
  - 监控：策略熵、输出多样性、奖励曲线
  - 缓解：熵 bonus、Clip-Higher、温度调节、KL 惩罚、动态采样
- RL 训练系统工程（rollout 线）
  - 核心认知：rollout、评分、更新与同步都可能成为瓶颈，应分别测量；算法和数据仍影响效果
  - Rollout 引擎与训练引擎分离
    - 训练用 Megatron/FSDP，rollout 用 vLLM/SGLang
    - 两套引擎的权重同步是吞吐主战场
    - 核心框架：verl、AReaL、SkyRL、RLHFuse
    - 工程要点：权重同步的频率、粒度、一致性是设计核心
  - 训练-推理数值一致性
    - 问题：同一样本在训练引擎和 rollout 引擎下 logprob 不一致
    - 后果：importance sampling 校正失效，PPO/GRPO 复现性和稳定性出问题
    - 这是比 reward hacking 更隐蔽的失效源
    - 工程要点：记录行为策略权重版本、生成分布和 logprob，测量引擎间误差；统一配置或采用有依据的校正并限制策略陈旧度，不要求所有算子完全相同
  - 异步 / 部分 rollout
    - 问题：长 CoT 里少数超长回答拖慢整批
    - 解法：分块生成、延迟过滤、异步 rollout
    - 这属于异步 rollout 调度；DAPO 的动态采样是过滤准确率全 0/全 1 等无有效组内优势的 prompt 组，不等于分块异步生成。见[DAPO 官方说明](https://dapo-sia.github.io/)
  - 长尾响应负载均衡
    - 问题：同一 batch 内响应长度差异巨大，长尾拖慢整体
    - 解法：动态 batch 组成、长度分桶、优先级调度
  - 工程价值
    - 采样系统约束预算内能开展的实验，效果还依赖奖励、算法、数据与基座
    - 采样吞吐上不去，算法再好也跑不动

### 3.5 参数高效微调（PEFT）

- LoRA
  - 核心：冻结原权重，注入低秩矩阵 $W = W_0 + BA$
  - 工程优势：训练参数较少；合并到兼容基础权重后可省去额外分支，多 LoRA 动态服务仍有开销；遗忘、稳定性和 adapter 组合需实测
- QLoRA：4-bit 量化基础模型 + LoRA
- PEFT 方法与优化配方：DoRA、VeRA；LoRA+ 调整 LoRA 矩阵的学习率配方，不是全参数训练
- GaLore 属于低显存全参数训练策略，不归为 PEFT；见[分布式训练与显存优化](#37-分布式训练与显存优化)
- 适用场景：领域适配、风格定制、资源受限场景

**选型与验收**：对照原始模型、adapter 微调与预算允许的全参数方案，记录 trainable 参数、峰值显存、吞吐和领域/通用留出集。低显存不等于低总成本，训练 loss 降低不等于泛化改善；LoRA 与 GaLore 不能只因名称含“低秩”就当作同一种机制。

### 3.6 量化感知训练（QAT）与部署衔接

- PTQ 在训练后用校准数据确定量化配置；QAT 在训练/微调中模拟量化误差，并可能学习量化参数，让模型适应部署精度。
- 常见机制：fake quantization、observer/scale、直通估计器（STE）；STE 是不可导舍入的梯度近似，不是精确导数。
- 固定与部署一致的权重/激活位宽、分组、缩放和目标内核；fake-quant 训练本身不证明低位宽部署加速。
- 比较原精度、PTQ、QAT 的任务质量与部署实测；校准/训练数据与留出测试隔离。QAT 可能改善质量，但成本更高且不保证无损。
- QLoRA 通常冻结量化基础权重、训练低秩 adapter，不等于把全部权重做常规 QAT；adapter 合并和再次量化后仍需回归。
- 部署决策见[推理部署](推理部署完整知识体系.md)，实践见[验收清单](实践与验收清单.md)。

### 3.7 分布式训练与显存优化

**先回答“哪一部分放不下或算不动”**

| 策略 | 切分对象与典型通信 | 适用条件与主要风险 |
| --- | --- | --- |
| 普通 DDP | 每 rank 复制模型/优化器，处理不同数据；归约梯度 | 模型和状态单卡能放下、需要吞吐；不自动节省模型状态显存，不同 rank 的 loss 分母需正确归一化 |
| ZeRO / FSDP | 沿数据并行组分片模型状态；按阶段归约梯度/聚合参数 | 状态显存成为瓶颈；通信、临时聚合峰值、分片 checkpoint 与恢复是额外成本，具体实现不同 |
| 张量并行 TP | 同一层的矩阵/头由多 rank 合作；需要集合通信 | 单层参数或计算过大；频繁通信要求合适互联，切分维度/算子契约必须一致 |
| 流水线并行 PP | 层分到不同 stage，传递激活及其梯度 | 模型纵向过大；microbatch 与调度影响流水线气泡、激活保留和负载均衡 |
| 专家并行 EP | 不同专家分布到不同 rank，路由 token 再聚合输出 | MoE 专家容量不足；All-to-All、负载不均、容量溢出与丢 token 需单独验证 |
| 序列/上下文并行 | 按具体方案切分序列相关激活或注意力计算；交换所需状态 | 长上下文激活成为瓶颈；边界、mask、位置与跨 rank 依赖必须正确，不是把文本随意断开 |

**ZeRO 分阶段理解**

ZeRO-1 分片优化器状态，ZeRO-2 再分片梯度，ZeRO-3 再分片参数；FSDP 的分片策略与 API 不等于所有 ZeRO 配置的直接替代。以四 rank 为例，某类持久状态若均匀分片，理想情况下每 rank 持有约四分之一；这不表示总显存也变成四分之一，因为激活、通信 bucket、临时完整层参数和工作区另计。阶段定义见 [DeepSpeed ZeRO 官方文档](https://deepspeed.readthedocs.io/en/stable/zero3.html)。

**实现与验收入口**

阅读 [Lesson 11](../11-DDP分布式训练.md) 的并行范式、DDP 实现、FSDP 与 ZeRO 对照；先复现单卡一步更新，再对比多卡等效全局 batch 的更新（浮点容差、有效 token 加权与归约因子），最后记录峰值显存、通信时间和扩展效率。GPU/多进程实验未运行时，不把 CPU 单元测试当作分布式认证。

- 混合并行：由上述策略组合，先确定各维度的进程组、数据分片和全局 batch 计算，不以“策略越多越先进”为目标
- 序列/上下文并行（Sequence/Context Parallelism）
  - 核心问题：长序列训练时单卡激活显存和注意力计算爆炸
  - 主要方法：Ring Attention、DeepSpeed-Ulysses、Megatron Context Parallel
  - 关键认知：序列并行是「训练侧」方案，RoPE 外推是「编码侧」方案，两者独立
- 【深度】ZeRO-3 通信开销量化
  - 理想化拆分下常估算为普通数据并行的约 1.5 倍；梯度累积、参数保留、预取与拓扑会改变实际通信
  - 拆解：前向 all-gather 参数、反向 all-gather 参数 + reduce-scatter 梯度
- 【深度】专家并行 All-to-All 优化
  - 通信模式：前向 2 个 All-to-All，反向 2 个
  - 优化：动态样本放置、计算通信重叠、通信压缩、分层通信、专家放置优化
- 底层算子与数值精度
  - FlashAttention：不物化完整注意力矩阵，将注意力中间存储从 O(n²) 降为线性级；不改变精确注意力的二次算术复杂度，总训练显存与加速依赖工作负载
  - FP8 训练：依赖硬件、缩放与高精度累积策略；8-bit 张量可减小存储，但总显存/速度不按位宽等比例变化。DeepSeek-V3 是公开实例，不宣称首个
- 混合精度训练：BF16/FP16 计算与高精度累积；是否保留 FP32 主权重、梯度和优化器状态的 dtype 取决于实现。FP16 常需 loss scaling，BF16 不应机械套用同一配置
- 显存占用拆解：模型参数 + 梯度 + 优化器状态 + 激活值
- GaLore：低秩投影梯度以减少优化器状态内存，仍更新完整权重；不能当成冻结基座的低秩 adapter，内存与吞吐收益依投影配置、优化器和工作负载实测。见[GaLore 原论文（2024）](https://arxiv.org/abs/2403.03507)
- 硬件与后端适配：例如 AXLearn（JAX + XLA）；按模型、算子、设备和通信支持实测，不把支持某后端等同于任意异构设备混训
- 训练的可复现性
  - 核心问题：同配置两次跑结果不同
  - 随机性来源
    - **Dataloader shuffle**：数据顺序随机
    - **算子非确定性**：CUDA 原子操作、非确定性归约
    - **集合通信顺序**：AllReduce 等的归约顺序不固定
    - **MoE 路由抖动**：Router 决策在边界情况下不稳定
  - 复现级别
    - **Bitwise 可复现**：完全相同的数值结果，代价是性能下降（确定性算子通常更慢）
    - **统计可复现**：结果分布相同，数值不完全一致
    - **实验可复现**：趋势和结论一致，具体数值有差异
  - 工程取舍
    - 生产训练通常只要求「统计可复现」
    - Debug 和复现实验时才要求 bitwise
    - Bitwise 复现需要：确定性算子 + 固定通信序 + 固定随机种子 + 正确恢复各设备/数据流 RNG、控制 Dropout 与算子非确定性；跨环境仍需验证
  - 关键认知
    - 数据卡解决「数据可追溯」，可复现性解决「训练可追溯」
    - 两者是工业级训练的两根支柱

### 3.8 训练正确性与恢复验收

- loss 对齐、mask、packing 和有效 token 加权先按[基础清单](基础与模型原理.md)验证；SFT 是否只训练 assistant token 要显式配置。
- DDP 中不同 rank 有效 token 数不同时，按全局有效 token 归一化，并考虑梯度归约的平均因子；不能各 rank 简单均值后再平均。
- 先过拟合小样本，再看独立验证集；记录有限值、梯度范数、学习率、训练吞吐与退化任务。
- checkpoint 除权重外还关联 optimizer/scheduler、step、RNG、数据/采样器状态；恢复后做不中断对照，教学实现不保证任意数据流精确续跑。
- 参考[训练循环](../07-训练循环与损失函数.md)、[CPU 实现与验收](实践与验收清单.md)。

## 四、LLM 训练 vs 推理 vs 微调

- 本质区别
  - 预训练：可以从随机权重开始学习通用能力；微调和继续预训练也是训练，不必从零开始
  - 微调：从预训练权重开始，适配特定任务，成本可控
  - 推理：参数冻结，仅前向传播，持续运营成本
- 成本口径
  - 记录参数量、token 数、数据/标注、训练时长、设备数量与单价
  - 后训练还包括 rollout、评分器和参考模型，不给缺少条件的统一 7B 价格
  - 总成本 = 计算资源时间费用 + 数据/标注/存储/评测与工程费用
- 选型判断
  - 需要从头学习通用能力 → 评估预训练的数据、算力与评测预算；小模型教学也可从头训练，规模化通用模型并非每个项目都需要
  - 需要领域适配 → 微调（LoRA/QLoRA/SFT）
  - 只需要使用 → 推理（API 调用或本地部署）

## 五、高级训练范式

这些是按问题选择的进阶路线，不是训练岗必须逐项采用的套餐。

| 方法 | 机制与适用条件 | 失败模式与最低验收 |
| --- | --- | --- |
| 继续预训练 | 从已有权重继续做语言建模，吸收领域分布；适用于有授权、足量且高质量语料的适配 | 领域指标变好而通用能力退化；控制数据混合、LR 与训练预算，固定领域/通用两套留出评测，不用它替代频繁变动的事实检索 |
| 蒸馏 | 用教师输出训练学生；响应级可对筛选后的教师序列做 SFT，logit 级可匹配温度化分布 | 教师错误和偏差会传递；logit 蒸馏需对齐词表/位置/分布，响应蒸馏需授权与质量筛选。与同规模未蒸馏学生比较质量、延迟和成本，教师成绩不能当学生成绩 |
| 模型合并 | 合并兼容 checkpoint 或相对共同基座的任务增量；不是把两个黑箱 API 拼起来 | 相同 shape 不保证参数语义可对齐；确认架构、tokenizer/词表、基座和模块映射，防止符号冲突与能力干扰。与各源模型逐任务对照，保存原模型以便回退 |
| 测试时计算 | 推理时增加采样、搜索或验证器选择的计算预算，不一定更新参数 | 更多 token 不保证更正确；固定任务和选择规则，在相同预算下比较质量、延迟与成本，检查验证器偏差。系统实现归[推理部署](推理部署完整知识体系.md)，不混入训练吞吐结论 |
| RLVR | 用可验证任务的奖励优化策略，是后训练路线；可结合上文 GRPO 等目标 | 验证器漏洞、奖励投机、测试泄漏、只提升可验证子任务；检查奖励实现、独立任务成功率与通用能力退化，不把任意自动评分称为可靠验证 |

蒸馏的经典软目标依据见 [Hinton 等（2015）](https://arxiv.org/abs/1503.02531)；合并中的参数干扰与符号冲突见 [TIES-Merging（2023）](https://arxiv.org/abs/2306.01708)。这些论文是机制实例，不保证任意 LLM 合并或蒸馏有效。实践交付按[验收清单](实践与验收清单.md)，奖励方法的公式和实现按 [Lesson 18](../18-RLHF-DPO-GRPO对齐技术.md)。

## 六、训练稳定性与故障处理

- 常见问题
  - Loss 不收敛、Loss NaN、Loss Spike、灾难性遗忘、Reward hacking、探索坍塌、训练崩溃、MoE 专家负载不均衡
- 【深度】Loss Spike 根因分类与处理
  - 根因：梯度异常、数值精度、数据问题、硬件 SDC、Router 抖动
  - 处理：回滚 + 降 LR、跳过 batch、AdaGC、数据检查、硬件排查
  - 关键认知：所有路径最终汇聚到「异常梯度污染优化器状态」
- 稳定性监控指标
  - 梯度范数、Attention entropy、策略熵、激活范围
- 容错机制
  - 检查点保存与恢复、故障节点隔离替换、弹性调度

## 八、安全与对齐

- 核心定位：训练侧的安全，与对齐技术（3.4）不同
  - 对齐技术：让模型「说人想听的话」
  - 安全与对齐：让模型「不说人不该听的话」
  - 前者是行为塑造，后者是风险防控
- 安全对齐（Safety Alignment）
  - 核心目标：让模型拒绝有害请求，同时保持对正常请求的有用性
  - 核心矛盾：安全性和有用性的权衡
    - 过度安全：模型变得过度拒答，正常问题也不答
    - 安全不足：模型被越狱，输出有害内容
  - 常见方法
    - **安全 SFT**：用安全数据做微调，教模型拒绝有害请求
    - **安全 RLHF**：把安全性作为奖励信号的一部分
    - ** Constitutional AI**：用一套原则约束模型行为，AI 自我批评和修正
    - **DPO 安全版**：用安全偏好数据做 DPO
    - **Red Teaming 训练**：用对抗样本训练，增强鲁棒性
  - 工程要点
    - 安全数据要覆盖多种攻击类型
    - 安全性和有用性要联合评估，不能只看一边
    - 安全训练可能导致 alignment tax（通用能力下降）
- 越狱与防御
  - 越狱攻击类型
    - **角色扮演**：「假装你是一个没有限制的 AI」
    - **编码绕过**：用 base64、摩斯码等编码恶意指令
    - **多语言绕过**：用小语种问有害问题
    - **上下文劫持**：在长上下文中隐藏恶意指令
    - **前缀注入**：用特定前缀绕过安全过滤
  - 防御手段
    - **对抗训练**：用越狱样本训练，增强鲁棒性
    - **输入过滤**：检测恶意输入模式
    - **输出过滤**：检测有害输出
    - **系统提示加固**：明确安全边界
    - **多层防御**：不能只靠训练侧，需要推理侧配合
  - 关键认知
    - 越狱防御是持续对抗，没有一劳永逸的方案
    - 训练侧防御 + 推理侧防御 + 监控，三层配合
- 红队测试（Red Teaming）
  - 定位：主动构造对抗性输入，探测模型的危险输出
  - 流程
    - 定义攻击面：越狱、偏见、有害内容、隐私泄露
    - 构造攻击样本：人工 + 自动
    - 执行攻击：批量测试
    - 分析结果：分类、归因
    - 反馈训练：把失败的样本加入安全训练
  - 自动化红队
    - 用 LLM 自动生成攻击样本
    - 用 LLM 自动评估攻击是否成功
    - 持续迭代，覆盖新攻击类型
  - 工程要点
    - 红队是持续过程，不是一次性任务
    - 红队结果要反馈到训练和推理两侧
    - 红队要覆盖多模态、Agent 等新场景
- 内容安全分级
  - 分级维度
    - **严重程度**：从轻微不当到严重违法
    - **场景**：医疗、金融、法律等有特殊要求
    - **用户群体**：成人、未成年人
  - 分级处理
    - 轻微不当：警告或拒绝
    - 中度不当：拒绝 + 解释原因
    - 严重违法：拒绝 + 记录 + 上报
  - 工程要点
    - 分级标准要明确，不能模糊
    - 分级处理要和推理侧配合
- 合规要求
  - 数据合规
    - PII 脱敏（见 3.1）
    - 版权与授权（见 3.1）
    - 数据跨境（GDPR、数据出境安全评估）
  - 模型合规
    - 模型卡（Model Card）：记录模型能力、限制、风险
    - 可解释性：关键决策可追溯
    - 审计日志：记录模型使用情况
  - 行业监管
    - 金融：金融监管要求
    - 医疗：医疗 AI 监管
    - 法律：法律服务监管
  - 工程要点
    - 合规要求随地区、行业变化
    - 合规要贯穿训练、推理、应用全链路
    - 合规文档要可审计
- 安全与对齐的工程实践
  - 分层防御
    - 数据层：清洗有害数据
    - 训练层：安全 SFT + 安全 RLHF
    - 推理层：输入输出过滤
    - 应用层：权限控制、审计日志
  - 关键原则
    - 不能只靠训练侧
    - 不能只靠推理侧
    - 必须纵深防御
  - 常见问题
    - 安全训练导致通用能力下降
    - 越狱防御被新攻击绕过
    - 合规要求变化快，跟不上
- 与对齐技术（3.4）的关系
  - 对齐技术：塑造模型行为，让模型「说人想听的话」
  - 安全与对齐：防控风险，让模型「不说人不该听的话」
  - 两者互补：对齐让模型有用，安全让模型无害
  - 两者可能冲突：过度对齐可能损害安全性，过度安全可能损害有用性
  - 工程实践：联合优化，不能只看一边

## 九、成本与算力工程

- 训练算力估算：密集 Transformer 常用总 FLOPs ≈ 6ND；主要近似参数矩阵乘法，不完整计长上下文注意力、重计算等。MoE 需按激活计算另估。
- 硬件效率：H100 SXM 的 FP16/BF16 Tensor Core 峰值 1979 TFLOPS 带稀疏性条件；对应密集理论峰值约 989.5 TFLOPS，不是实测吞吐。见[NVIDIA 规格及脚注](https://www.nvidia.com/en-us/data-center/h100/)。
- MFU：按明确的模型 FLOPs/秒除以匹配硬件与精度的理论峰值；密集任务不能以稀疏峰值作分母。实际 MFU 需测量，不预设 40%。
- 成本构成：预训练一次性资本支出、后训练算力+标注+评分器、推理持续性运营支出

## 十一、落地工程难点

- 数据质量（地基瓶颈）
- 分布式训练调试
- MoE 训练
- 长上下文训练：位置适配、注意力实现与并行策略按架构和资源选择，序列并行不是必选项
- 硬件异构
- 训练稳定性
- 对齐的副作用
- 评分器成本
- 评估可信度
- 国产算力适配
- 合成数据自噬
- RL 训练系统：rollout 引擎、权重同步、训练-推理数值一致性
- Tokenizer 质量：迁移成本高，应预先验证并与模型版本绑定
- 训练可复现性：同配置两次跑结果不同
- **【新增】安全与有用性的权衡**：安全训练可能损害通用能力，过度安全导致过度拒答
- **【新增】越狱防御持续对抗**：新攻击手段层出不穷，防御没有终点
- **【新增】合规要求变化快**：不同地区、行业监管不同，需持续跟踪
- 核心认知：预训练是大厂游戏，微调和对齐是应用层核心能力

### 11.1 LLM 训练常见反模式

- 忽视数据质量盲目堆规模
- 质量过滤拍脑袋定阈值
- SFT 数据多样性不足
- SFT 只堆数量不重质量
- 未验证策略漂移就任意取消约束
- 后训练不评估通用能力回退与数据配比
- 忽视 RL 评分器成本
- 全参数微调小数据集
- 忽视显存占用拆解
- 假定训练集群同构
- MoE 不做负载均衡
- 不评估当前基座就机械添加或跳过中期训练
- 不监控训练稳定性指标
- 长上下文外推不按具体方法做校准和回归
- 合成数据不留真实锚点
- RL 训练不监控策略熵
- 长上下文仅改位置参数，不验证质量、显存与吞吐
- 超参不迁移直接 scale up
- RL 训练不做训练-推理数值一致性校验
- Tokenizer 不做下游任务验证
- 不追求训练可复现性
- 不做消融就假设课程设计一定优于随机采样
- **【新增】只做对齐不做安全**
  - 表现：只做 SFT 和 RLHF，不做安全训练
  - 后果：模型容易被越狱，输出有害内容
  - 正解：对齐 + 安全联合训练，两者不能偏废
- **【新增】安全训练过度导致过度拒答**
  - 表现：安全数据占比过高，模型对正常问题也拒答
  - 后果：可用性下降，用户体验差
  - 正解：安全性和有用性联合评估，平衡两者
- **【新增】只做训练侧安全不做推理侧防御**
  - 表现：只靠安全训练，推理侧不做输入输出过滤
  - 后果：新攻击绕过训练侧防御
  - 正解：训练侧 + 推理侧 + 监控，三层配合
- **【新增】红队一次性不做持续迭代**
  - 表现：上线前红队一次，之后不再测
  - 后果：新攻击手段出现时无防御
  - 正解：红队是持续过程，定期迭代，覆盖新攻击类型
- **【新增】不记录模型卡和审计日志**
  - 表现：模型能力、限制、风险无文档
  - 后果：合规审计时无法追溯
  - 正解：模型卡 + 审计日志，合规必备
- **【新增】忽视 alignment tax**
  - 表现：安全训练后不评估通用能力
  - 后果：通用能力下降不知道
  - 正解：安全训练后必须评估通用能力，权衡安全性和有用性
