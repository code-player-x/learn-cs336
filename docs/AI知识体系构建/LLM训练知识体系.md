# LLM 训练完整知识体系

> 本版本在上一版基础上，补入安全与对齐章节。新增内容以 **【新增】** 标记。

## 一、LLM 训练基础认知

- 核心定义
  - 全称：大语言模型训练（Large Language Model Training）
  - 核心解决：让模型从「随机权重」变成「能理解、能生成、能对齐人类意图」的通用智能体
  - 本质：通过海量数据和算力，把语言知识和推理能力「压缩」进模型参数
- 与推理的本质区别
  - 推理：输入 → 输出，模型参数冻结，一次前向传播
  - 训练：前向传播 + 反向传播 + 参数更新，多轮迭代，参数持续变化
- 三大核心阶段
  - 预训练（Pre-training）：海量文本上学习语言和世界知识
  - 指令微调（SFT）：用指令-回答数据教会模型「听懂人话」
  - 对齐（Alignment）：用人类偏好让模型「说人想听的话」
- 核心价值
  - 能力注入：把知识、语言、推理能力写进参数
  - 行为塑造：让模型遵循指令、拒绝不当请求、输出符合人类偏好
  - 领域适配：通过微调让通用模型适配垂直领域
- 文档定位声明
  - 本文档定位纯训练工程视角
  - 不含能力边界/哲学讨论（意向性、持续学习不可能、真值缺失等属于 AI 哲学范畴，不在工程体系内）
  - 不含多模态训练（视觉 encoder 挂载、模态对齐等属于独立专题卷）
  - 不含推理部署（量化、KV Cache、推理引擎等属于推理部署体系）
  - 存在一条范式天花板讨论，不在本卷范围内，读者需知工程体系不等于模型认知的全貌

## 二、LLM 训练完整工作流程

- 三阶段流水线（工业界标准）
  - Phase 1：预训练（Pre-training）
    - 目标：学习通用语言理解与生成能力
    - 数据：海量文本语料（1-36 万亿 token）
    - 方法：自监督学习，Next-Token Prediction
    - 产出：Base Model（有知识、能续写，但不会「对话」）
  - Phase 2：监督微调（SFT / Instruction Tuning）
    - 目标：教会模型遵循指令、以对话格式回答
    - 数据：指令-回答对（1-10M 条高质量样本）
    - 方法：在指令数据上做监督学习
    - 产出：Instruct Model（能对话、能执行任务）
  - Phase 3：对齐（Alignment / RLHF / DPO / GRPO）
    - 目标：让模型输出符合人类偏好、安全、有用
    - 数据：人类偏好数据（pairwise comparisons）或可验证奖励
    - 方法：强化学习或直接偏好优化
    - 产出：Aligned Model（最终部署版本）
- 关键认知
  - 预训练提供「地基」，后训练决定「建成什么楼」
  - 后训练（SFT + 对齐）现在决定了模型的大部分可用能力
  - 三阶段不是可选的，是工业界的标准流程

### 2.1 预训练（Pre-training）完整流程

- Step 1：数据收集
  - 主要来源：网页（Common Crawl）、书籍、论文（arXiv/PubMed）、代码（GitHub）、对话数据
  - 数据规模：GPT-3 300B tokens；LLaMA 2 2T；LLaMA 3 15T；DeepSeek V3 14.8T；Qwen 3 36T
- Step 2：数据预处理
  - 清洗步骤：去重、质量过滤、毒性移除、语言识别、PII 减少
  - 数据混合策略：按质量与多样性分配采样权重，而非均匀采样
  - 质量评估维度：表达清晰度、结构完整性、内容可信度、知识丰富度、逻辑深度
- Step 3：分词（Tokenization）
  - 子词算法：BPE（GPT 系列）、WordPiece（BERT）、Unigram（SentencePiece）
  - 词表大小：32K-200K，LLaMA 3 使用 128K
  - Tokenizer 质量对能力的隐性影响
    - 核心认知：分词器一旦训练完就锁死，后期改不动，是「结构性决策」
    - 非拉丁语系的 token 膨胀
      - 现象：同一段中文，用英文分词器可能比用中文优化分词器多出 2-3 倍 token
      - 后果：直接抬高训练和推理成本、稀释有效上下文窗口、降低中文任务表现
      - 工程要点：中文/日文/韩文等非拉丁语系必须有专门的分词优化
    - 数字与代码的分词方式
      - 现象：数字按位（1, 2, 3）vs 按段（123）分词，对算术能力影响显著
      - 代码：缩进、符号、关键字的分词方式影响代码生成质量
      - 工程要点：分词器设计时要做下游任务验证，不能只看压缩率
    - 分词决策的不可逆性
      - 词表一旦确定，所有预训练数据都要按它切
      - 后期换分词器 = 全部重训
      - 工程要点：分词器设计要在预训练开始前充分验证
- Step 4：模型架构选择
  - Decoder-only（GPT 风格）为主流
  - 关键超参：层数 12-126、隐藏维度 768-16384、注意力头 12-128、上下文窗口 2K-32K
- Step 5：预训练目标
  - 自回归语言建模：Next-Token Prediction
  - 损失函数：负对数似然 \(\mathcal{L}(\theta) = -\sum \log P(x_t|x_{<t};\theta)\)
  - 变体：因果掩码（左到右）、Fill-in-the-Middle（代码模型）
- Step 6：训练优化
  - 优化器：AdamW（主流），Lion / Shampoo / Muon 为新兴选择
  - 学习率：Warmup + Cosine Decay，或 WSD（Warmup-Stable-Decay）
  - 梯度裁剪、混合精度训练（BF16/FP16/FP8）
  - 批量大小：1M-10M tokens
- Step 7：分布式训练
  - 数据并行（Data Parallelism）
  - 张量并行（Tensor Parallelism）
  - 流水线并行（Pipeline Parallelism）
  - 序列/上下文并行（Sequence/Context Parallelism）
  - ZeRO 优化（DeepSpeed）
- Step 8：评估与 Scaling
  - 监控指标：Loss 曲线、Perplexity、下游任务表现
  - Scaling Laws：\(L(N, D) = (N_c/N)^{\alpha_N}\)

### 2.2 中期训练 / 退火阶段（Mid-training / Annealing）

- 定位：预训练和后训练之间的独立阶段，不是预训练的尾巴
- 核心目标：从「记忆」转向「抽象」
  - 预训练后期在低质数据上已接近容量上限
  - 切换到高质量数据 + 降低学习率，模型学会提取结构化推理和事实性
- 关键设计
  - 数据切换：从通用网页数据切到高质量领域数据（数学、代码、指令格式）
  - 学习率退火：从预训练学习率线性衰减到接近 0
  - 上下文扩展：在中期训练阶段做长上下文外推（YaRN/NTK-aware），比从头训练长上下文更高效
- 典型实践
  - Llama 3：预训练 15T token，中期训练切换 Dolmino Mix 1124 高质量数据
  - DeepSeek：类似的中期训练流程，为 SFT 提供更好的起点
- 为什么独立
  - 数据分布、学习率策略、评估重点都与标准预训练不同
  - 产出直接决定 SFT 的起点质量
  - 有研究将其视为独立阶段并给出系统化分类

## 三、核心组件详解

### 3.1 数据工程

- 数据收集
  - 来源多样性：网页、书籍、论文、代码、对话
  - 规模与质量权衡：数据质量比规模更重要
- 数据清洗
  - 去重：精确去重 + 模糊去重
  - 质量过滤：基于规则 + 基于模型的评分
  - 毒性移除、PII 脱敏
- 数据混合
  - 传统方法：按领域权重均匀采样
  - 现代方法：按样本质量与多样性分配权重
  - 【深度】自动化混合方法
    - **DoReMi（Domain Reweighting with Minimax Optimization）**
      - 核心目标：最小化各领域上的「最坏情况超额损失」
      - 具体计算流程
        - Step 1：用初始权重训练参考模型（280M）
        - Step 2：用 Group DRO 训练代理模型，动态调整各领域采样权重
        - Step 3：取 DRO 训练过程中领域权重的平均值
        - Step 4：用这些权重训练大模型（8B，30 倍于代理模型）
      - 关键数据：280M 代理模型（8% 大模型算力）使 8B 模型平均下游准确率提升 6.5 个百分点，达到基线准确率速度快 2.6 倍
    - **BiMix（Bivariate Data Mixing Law）**
      - 公式：\(L_i(r_i, s) = \frac{A_i}{r_i^{\alpha_i}} \left( \frac{B_i}{s^{\beta_i}} + C_i \right)\)
      - 直觉：\(B_i / s^{\beta_i}\) 捕捉训练步数缩放，\(1 / r_i^{\alpha_i}\) 捕捉领域比例缩放，\(C_i\) 是不可约损失
      - 关键发现：熵驱动的数据混合（特别是条件熵）可达到与计算密集型方法相当甚至更好的效果
  - 动态混合：训练过程中调整数据配比
  - 课程学习 / 数据排序
    - 核心问题：配比决定「喂什么比例」，课程决定「什么顺序喂」，两者是正交维度
    - 课程维度
      - **难度课程**：先易后难，或先难后易
      - **长度课程**：从短序列逐步过渡到长序列
      - **质量课程**：从高质量数据开始，逐步引入更多样数据
    - 典型方法
      - **Length Curriculum**：从小 seq_len 开始，逐步增大，降低初期训练不稳定
      - **Difficulty Curriculum**：按样本难度（如 loss 值）排序，从易到难
      - **Data Ordering**：研究显示数据顺序对收敛速度和终点效果有显著影响
    - 与数据混合的关系
      - 混合：决定「不同来源的比例」
      - 课程：决定「同一来源内部的顺序」
      - 两者正交，可以组合使用
    - 工程要点
      - 课程设计要实验验证，不是理论最优就是实际最优
      - 过长课程可能浪费训练步数，过短可能没效果
- 数据质量评估框架
  - 7 个维度：表达清晰度、完整性、结构、可信度、重要性、知识丰富度、逻辑深度
  - 评分范围：0-10，用于样本级筛选
- 质量过滤的工程校准
  - 核心问题：过滤太狠丢多样性，过滤太松等于没滤
  - 关键认知：质量过滤的本质是「去噪」，不是「找金子」
  - 正确做法：用小规模代理模型做校准实验，确定过滤阈值
- 合成数据（Synthetic Data）
  - 地位：不再是「补充」，而是 SFT 和对齐的重要来源
  - 典型用途
    - 弥补稀缺领域：小语种、专业领域、低资源任务
    - 质量增强：用强模型生成高质量推理链，蒸馏给小模型
    - 规模扩展：PersonaHub 等方案用 10 亿 persona 规模化生成数据
  - 代表数据集：OpenThoughts-114k、Nemotron 系列
  - 风险：模型生成数据的偏差会被继承，需要质量过滤和多样性控制
  - Model Collapse（合成数据自噬）
    - 核心问题：用模型生成的数据反复训练模型，分布尾部塌缩、性能退化
    - 失效机制：第一代数据分布比真实数据窄 → 第二代更窄 → 迭代 N 代尾部消失
    - 两种塌缩模式：早期塌缩（快速丢失尾部，整体性能暂时保持）、晚期塌缩（性能全面退化，不可逆）
    - 防护栏：保留真实数据锚点、控制代际比例、质量过滤、多样性监控
- 数据版本化与数据卡（Dataset Card）
  - 核心：记录来源、清洗步骤、过滤规则、风险评估
  - 目的：可追溯、可审计、可复现
  - 工业级训练管线的标配，合规审计的必需品
  - 版权与授权合规
    - 与 PII 脱敏并列的另一根合规支柱
    - 现实风险：NYT 诉 OpenAI 等诉讼，fair use 争议
    - 数据卡应记录：授权链、版权状态、使用限制、溯源信息
    - 工程要点：数据溯源必须从采集阶段开始记录，授权信息结构化存储

### 3.2 模型架构

- Transformer 核心组件
  - 自注意力（Self-Attention）：\(Attention(Q,K,V) = softmax(QK^T/\sqrt{d_k})V\)
  - 多头注意力（MHA / MQA / GQA）：MHA 多组 KV，MQA 单组 KV，GQA 折中
  - 位置编码：RoPE（旋转位置编码）为主流
  - 激活函数：SwiGLU / GELU
  - 归一化：LayerNorm / RMSNorm
- Decoder-only 架构
  - 因果掩码（Causal Mask）：保证自回归生成
  - 主流模型：GPT、LLaMA、Qwen、DeepSeek
- MoE（Mixture of Experts）架构
  - 核心设计：总参数大、激活参数小
    - 例子：DeepSeek-V3 总参数 671B，激活参数 37B
  - 核心组件：Router、Experts、Top-K 路由
  - 【深度】MoE 的 auxiliary loss 形式与优缺点
    - 传统 auxiliary loss：\(L = L_{model} + \alpha L_a + \beta L_z\)，辅助 loss 与主 loss 存在冲突
    - Auxiliary-Loss-Free Load Balancing：可学习 bias 项动态调整路由分数，不干扰主 loss
    - Batch-wise auxiliary loss：只在 batch 级别强制均衡
  - 训练侧核心痛点
    - 专家负载不均衡：auxiliary loss、专家容量限制、Router 温度调节、bias 调节
    - All-to-All 通信瓶颈：专家并行、通信压缩、计算通信重叠、动态样本放置
    - 训练不稳定性：Router 冻结策略、分阶段训练、梯度裁剪
  - 与 Dense 架构的权衡：总参数更大 vs 训练复杂度高
  - 主流采用：DeepSeek-V3/R1、Qwen 3、Mixtral、Switch Transformer
- 非 Transformer 架构：SSM 系列
  - Mamba：线性复杂度，长序列有优势
  - 与 Transformer 的关系：重叠但不同的表达容量，混合架构可能更优
  - 当前状态：学术活跃，工业部署仍以 Transformer 为主
- 【深度】长上下文外推（RoPE Scaling）
  - 主要方法：PI、NTK-aware、YaRN、LongRoPE
  - YaRN 的 attention temperature：\(\frac{1}{\sqrt{t}} = 0.1 \ln s + 1\)
  - LongRoPE 三阶段：4K→256K→2048K→短上下文恢复
  - 关键认知：分频率插值 + 注意力温度校准的组合
- 缩放定律（Scaling Laws）
  - Chinchilla 配比：参数量:数据量 ≈ 1:20 最优
  - 新趋势：小参数 + 超大数据（8B 模型喂 15T token）
  - 涌现能力测量争议：可能是评估指标非线性导致的假象
  - 超参迁移方法论（µP + lr–batch 缩放）
    - µP：隐藏层权重初始化方差按 \(1/\text{width}\) 缩放，学习率按 \(1/\text{width}\) 缩放
    - 效果：小模型搜到的最优 lr 可直接迁移到大模型
    - lr–batch 缩放：线性缩放（小 batch）、平方根缩放（大 batch）、Critical Batch Size
    - 工具：`mup` 包（Microsoft）

### 3.3 监督微调（SFT）

- 核心目标：教会模型遵循指令、输出对话格式
- 数据构造
  - 指令-回答对
  - 多样性关键：指令多样性带来零样本泛化能力
  - Chain-of-Thought 格式
  - 核心认知：数据质量 > 数量
- 训练细节
  - 只对 assistant 回复计算 loss，mask 掉 prompt token
  - 学习率远低于预训练
  - 数据量：1-10M 条高质量样本
- SFT 的局限
  - 只能从示范中学习，无法表达偏好
  - 训练数据中的错误会被学习
  - 对同一回答的所有 token 同等对待

### 3.4 对齐技术（Alignment）

- 拒绝采样自训练（RFT）
  - 定位：SFT 和对齐之间的标准桥梁
  - 流程：生成多个回答 → 奖励模型打分 → 筛最高分 → SFT → 循环
  - 局限：依赖奖励模型质量，分布偏移，迭代成本
- RLHF（Reinforcement Learning from Human Feedback）
  - 三阶段：SFT → 奖励模型 → PPO
  - 奖励模型：Bradley-Terry 偏好模型
  - PPO：最大化奖励 - KL 惩罚
  - RL 后训练成本拆解：策略采样 + 评分器推理 + 梯度更新
  - 生产数据：MiMo-V2.6 的 Pro 版 262 万美元、Flash 版 85 万美元，评分器占 12.7%
- RLAIF
  - 用强模型代替人类标注偏好，大幅降低标注成本
- DPO
  - 最优 RLHF 策略有闭式解，无需奖励模型、无需 RL 采样
  - 局限：长度偏差、依赖参考模型、需要成对偏好数据
- 【深度】GRPO
  - 组内归一化：\(\hat{A}_i = \frac{r_i - \text{mean}(\{r_1, \ldots, r_G\})}{\text{std}(\{r_1, \ldots, r_G\})}\)
  - 消除 critic，内存减半
  - 采用者：DeepSeek-R1
- 【深度】DAPO
  - Clip-Higher：解耦上界和下界，鼓励探索，防止熵坍缩
  - 四项技术：Clip-Higher、动态采样、Token 级策略梯度损失、超长奖励塑形
- SimPO / KTO / ORPO / RLVR
- RL 训练的探索坍塌（Entropy Collapse）
  - 核心问题：策略熵持续下降，输出多样性消失，奖励停止上涨
  - 与 reward hacking 的区别
  - 监控：策略熵、输出多样性、奖励曲线
  - 缓解：熵 bonus、Clip-Higher、温度调节、KL 惩罚、动态采样
- RL 训练系统工程（rollout 线）
  - 核心认知：RL 训练真正的瓶颈不在算法，在采样系统
  - Rollout 引擎与训练引擎分离
    - 训练用 Megatron/FSDP，rollout 用 vLLM/SGLang
    - 两套引擎的权重同步是吞吐主战场
    - 核心框架：verl、AReaL、SkyRL、RLHFuse
    - 工程要点：权重同步的频率、粒度、一致性是设计核心
  - 训练-推理数值一致性
    - 问题：同一样本在训练引擎和 rollout 引擎下 logprob 不一致
    - 后果：importance sampling 校正失效，PPO/GRPO 复现性和稳定性出问题
    - 这是比 reward hacking 更隐蔽的失效源
    - 工程要点：训练和推理必须用同一套算子、同一精度、同一数值路径
  - 异步 / 部分 rollout
    - 问题：长 CoT 里少数超长回答拖慢整批
    - 解法：分块生成、延迟过滤、异步 rollout
    - 这是 DAPO「动态采样」背后的系统动因
  - 长尾响应负载均衡
    - 问题：同一 batch 内响应长度差异巨大，长尾拖慢整体
    - 解法：动态 batch 组成、长度分桶、优先级调度
  - 工程价值
    - RL 算法的效果上限由采样系统决定
    - 采样吞吐上不去，算法再好也跑不动

### 3.5 参数高效微调（PEFT）

- LoRA
  - 核心：冻结原权重，注入低秩矩阵 \(W = W_0 + BA\)
  - 工程优势：推理零开销、部署即插即拔、缓解灾难性遗忘、训练更稳定、权重可组合
- QLoRA：4-bit 量化基础模型 + LoRA
- 主流 PEFT 变体：DoRA、VeRA、LoRA+、GaLore
- 适用场景：领域适配、风格定制、资源受限场景

### 3.6 分布式训练与显存优化

- 并行策略
  - 数据并行、张量并行、流水线并行、专家并行、混合并行
- 序列/上下文并行（Sequence/Context Parallelism）
  - 核心问题：长序列训练时单卡激活显存和注意力计算爆炸
  - 主要方法：Ring Attention、DeepSpeed-Ulysses、Megatron Context Parallel
  - 关键认知：序列并行是「训练侧」方案，RoPE 外推是「编码侧」方案，两者独立
- 【深度】ZeRO-3 通信开销量化
  - ZeRO-3 通信量是标准数据并行的 1.5 倍
  - 拆解：前向 all-gather 参数、反向 all-gather 参数 + reduce-scatter 梯度
- 【深度】专家并行 All-to-All 优化
  - 通信模式：前向 2 个 All-to-All，反向 2 个
  - 优化：动态样本放置、计算通信重叠、通信压缩、分层通信、专家放置优化
- 底层算子与数值精度
  - FlashAttention（v1/v2/v3）：显存从 O(n²) 降到 O(n)，速度提升 2-4 倍
  - FP8 训练：相比 BF16 速度提升 1.5-2 倍，显存降低 50%，DeepSeek-V3 首次跑通
- 混合精度训练：BF16/FP16 前向反向，FP32 主权重
- 显存占用拆解：模型参数 + 梯度 + 优化器状态 + 激活值
- 硬件异构训练：AXLearn（JAX + XLA + GSPMD），DeepSeek V4 适配昇腾
- 训练的可复现性
  - 核心问题：同配置两次跑结果不同
  - 随机性来源
    - **Dataloader shuffle**：数据顺序随机
    - **算子非确定性**：CUDA 原子操作、非确定性归约
    - **集合通信顺序**：AllReduce 等的归约顺序不固定
    - **MoE 路由抖动**：Router 决策在边界情况下不稳定
  - 复现级别
    - **Bitwise 可复现**：完全相同的数值结果，代价是性能下降（确定性算子通常更慢）
    - **统计可复现**：结果分布相同，数值不完全一致
    - **实验可复现**：趋势和结论一致，具体数值有差异
  - 工程取舍
    - 生产训练通常只要求「统计可复现」
    - Debug 和复现实验时才要求 bitwise
    - Bitwise 复现需要：确定性算子 + 固定通信序 + 固定随机种子 + 关闭 FlashAttention 的随机性
  - 关键认知
    - 数据卡解决「数据可追溯」，可复现性解决「训练可追溯」
    - 两者是工业级训练的两根支柱

## 四、LLM 训练 vs 推理 vs 微调

- 本质区别
  - 训练：从随机权重开始，学习通用能力，成本极高
  - 微调：从预训练权重开始，适配特定任务，成本可控
  - 推理：参数冻结，仅前向传播，持续运营成本
- 成本对比（7B 模型）
  - 预训练：$300k 算力
  - SFT：$100 算力 + $25k 标注
  - RLHF：$100 算力（纯计算，不含评分器开销）
- 选型判断
  - 需要通用能力 → 预训练（只有大厂/大机构做）
  - 需要领域适配 → 微调（LoRA/QLoRA/SFT）
  - 只需要使用 → 推理（API 调用或本地部署）

## 八、安全与对齐

- 核心定位：训练侧的安全，与对齐技术（3.4）不同
  - 对齐技术：让模型「说人想听的话」
  - 安全与对齐：让模型「不说人不该听的话」
  - 前者是行为塑造，后者是风险防控
- 安全对齐（Safety Alignment）
  - 核心目标：让模型拒绝有害请求，同时保持对正常请求的有用性
  - 核心矛盾：安全性和有用性的权衡
    - 过度安全：模型变得过度拒答，正常问题也不答
    - 安全不足：模型被越狱，输出有害内容
  - 常见方法
    - **安全 SFT**：用安全数据做微调，教模型拒绝有害请求
    - **安全 RLHF**：把安全性作为奖励信号的一部分
    - ** Constitutional AI**：用一套原则约束模型行为，AI 自我批评和修正
    - **DPO 安全版**：用安全偏好数据做 DPO
    - **Red Teaming 训练**：用对抗样本训练，增强鲁棒性
  - 工程要点
    - 安全数据要覆盖多种攻击类型
    - 安全性和有用性要联合评估，不能只看一边
    - 安全训练可能导致 alignment tax（通用能力下降）
- 越狱与防御
  - 越狱攻击类型
    - **角色扮演**：「假装你是一个没有限制的 AI」
    - **编码绕过**：用 base64、摩斯码等编码恶意指令
    - **多语言绕过**：用小语种问有害问题
    - **上下文劫持**：在长上下文中隐藏恶意指令
    - **前缀注入**：用特定前缀绕过安全过滤
  - 防御手段
    - **对抗训练**：用越狱样本训练，增强鲁棒性
    - **输入过滤**：检测恶意输入模式
    - **输出过滤**：检测有害输出
    - **系统提示加固**：明确安全边界
    - **多层防御**：不能只靠训练侧，需要推理侧配合
  - 关键认知
    - 越狱防御是持续对抗，没有一劳永逸的方案
    - 训练侧防御 + 推理侧防御 + 监控，三层配合
- 红队测试（Red Teaming）
  - 定位：主动构造对抗性输入，探测模型的危险输出
  - 流程
    - 定义攻击面：越狱、偏见、有害内容、隐私泄露
    - 构造攻击样本：人工 + 自动
    - 执行攻击：批量测试
    - 分析结果：分类、归因
    - 反馈训练：把失败的样本加入安全训练
  - 自动化红队
    - 用 LLM 自动生成攻击样本
    - 用 LLM 自动评估攻击是否成功
    - 持续迭代，覆盖新攻击类型
  - 工程要点
    - 红队是持续过程，不是一次性任务
    - 红队结果要反馈到训练和推理两侧
    - 红队要覆盖多模态、Agent 等新场景
- 内容安全分级
  - 分级维度
    - **严重程度**：从轻微不当到严重违法
    - **场景**：医疗、金融、法律等有特殊要求
    - **用户群体**：成人、未成年人
  - 分级处理
    - 轻微不当：警告或拒绝
    - 中度不当：拒绝 + 解释原因
    - 严重违法：拒绝 + 记录 + 上报
  - 工程要点
    - 分级标准要明确，不能模糊
    - 分级处理要和推理侧配合
- 合规要求
  - 数据合规
    - PII 脱敏（见 3.1）
    - 版权与授权（见 3.1）
    - 数据跨境（GDPR、数据出境安全评估）
  - 模型合规
    - 模型卡（Model Card）：记录模型能力、限制、风险
    - 可解释性：关键决策可追溯
    - 审计日志：记录模型使用情况
  - 行业监管
    - 金融：金融监管要求
    - 医疗：医疗 AI 监管
    - 法律：法律服务监管
  - 工程要点
    - 合规要求随地区、行业变化
    - 合规要贯穿训练、推理、应用全链路
    - 合规文档要可审计
- 安全与对齐的工程实践
  - 分层防御
    - 数据层：清洗有害数据
    - 训练层：安全 SFT + 安全 RLHF
    - 推理层：输入输出过滤
    - 应用层：权限控制、审计日志
  - 关键原则
    - 不能只靠训练侧
    - 不能只靠推理侧
    - 必须纵深防御
  - 常见问题
    - 安全训练导致通用能力下降
    - 越狱防御被新攻击绕过
    - 合规要求变化快，跟不上
- 与对齐技术（3.4）的关系
  - 对齐技术：塑造模型行为，让模型「说人想听的话」
  - 安全与对齐：防控风险，让模型「不说人不该听的话」
  - 两者互补：对齐让模型有用，安全让模型无害
  - 两者可能冲突：过度对齐可能损害安全性，过度安全可能损害有用性
  - 工程实践：联合优化，不能只看一边

### 11.1 LLM 训练常见反模式

- 忽视数据质量盲目堆规模
- 质量过滤拍脑袋定阈值
- SFT 数据多样性不足
- SFT 只堆数量不重质量
- RLHF 不做 KL 惩罚
- 用 RLHF 时不混合预训练数据
- 忽视 RL 评分器成本
- 全参数微调小数据集
- 忽视显存占用拆解
- 假定训练集群同构
- MoE 不做负载均衡
- 跳过中期训练直接 SFT
- 不监控训练稳定性指标
- 长上下文外推不做温度校准
- 合成数据不留真实锚点
- RL 训练不监控策略熵
- 长上下文只做 RoPE 外推不做序列并行
- 超参不迁移直接 scale up
- RL 训练不做训练-推理数值一致性校验
- Tokenizer 不做下游任务验证
- 不追求训练可复现性
- 只有数据混合没有课程设计
- **【新增】只做对齐不做安全**
  - 表现：只做 SFT 和 RLHF，不做安全训练
  - 后果：模型容易被越狱，输出有害内容
  - 正解：对齐 + 安全联合训练，两者不能偏废
- **【新增】安全训练过度导致过度拒答**
  - 表现：安全数据占比过高，模型对正常问题也拒答
  - 后果：可用性下降，用户体验差
  - 正解：安全性和有用性联合评估，平衡两者
- **【新增】只做训练侧安全不做推理侧防御**
  - 表现：只靠安全训练，推理侧不做输入输出过滤
  - 后果：新攻击绕过训练侧防御
  - 正解：训练侧 + 推理侧 + 监控，三层配合
- **【新增】红队一次性不做持续迭代**
  - 表现：上线前红队一次，之后不再测
  - 后果：新攻击手段出现时无防御
  - 正解：红队是持续过程，定期迭代，覆盖新攻击类型
- **【新增】不记录模型卡和审计日志**
  - 表现：模型能力、限制、风险无文档
  - 后果：合规审计时无法追溯
  - 正解：模型卡 + 审计日志，合规必备
- **【新增】忽视 alignment tax**
  - 表现：安全训练后不评估通用能力
  - 后果：通用能力下降不知道
  - 正解：安全训练后必须评估通用能力，权衡安全性和有用性
